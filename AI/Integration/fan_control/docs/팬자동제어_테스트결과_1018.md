# 팬 자동제어 테스트 결과 (10/18)

## 요약

- 연기로 PM이 올라오면 제어기가 바로 팬을 올리고, PM이 내려오면 다시 약하게 낮추는 동작을 가상 데이터 시험에서 확인했습니다. 연기 감지(PM 50 초과) 후 2초 만에 100/60으로 올라갔습니다.
- 같은 가상 상황에서 마감 140초 설정의 모델은 고정 100/100과 거의 같은 속도(PM50 아래 복귀 116초 대 114초)로 내려오면서 추정 에너지는 절반 이하(163 J 대 354 J)였습니다.
- 테스트 중 발견한 문제 5가지를 고쳤습니다(아래 4번).
- 아직 확인하지 못한 것: 모델 제어기를 실제 젯슨과 센서, 팬에 연결한 실행 기록, 실제 챔버에서의 회복 속도, 새 실험 표본에서의 예측 정확도.

## 1. 테스트 목적과 대상

- 목적: PM이 올라왔을 때 팬을 제때 올리고, 내려오면 추정 에너지가 적은 조합으로 낮추는지 확인합니다.
- 대상: 20회 실험으로 만든 감쇠 시간표를 쓰는 예측 기반 제어기(`fan_controller.py`). 센서 읽기와 팬 출력만 하드웨어에 연결하면 됩니다(`run_on_jetson.py`).
- 제어 규칙: 5초마다 최근 3개 PM의 중앙값으로 판단, 조합 변경 후 최소 15초 유지, PM이 뚜렷하게 오르는 중이면 가장 빠른 조합으로 즉시 상승, 측정값이 500을 넘으면 가장 빠른 조합, 센서가 10초 넘게 끊기면 100/100.

## 2. 시험 A: 가상 데이터 폐루프 시험

평소 PM 36에서 130초에 연기가 올라와 약 980까지 간 뒤, 팬 조합에 따라 내려오는 가상 환경입니다. 센서 잡음(2%와 ±1)과 센서 누락(1초, 10초, 15초)을 넣었습니다. 내려가는 속도는 모델 시간표에서 환산한 값이라, 제어기의 동작을 보는 시험이고 모델 정확도를 확인한 것은 아닙니다.

| 정책 | 최고 PM | PM50 아래 복귀(연기 시작 후) | 연기 후 170초 추정 에너지 |
| --- | --- | --- | --- |
| 모델 (마감 140초) | 976 | 116초 | 163 J |
| 모델 (마감 없음) | 976 | 164초 | 77 J |
| 고정 35/35 | 1196 | 188초 | 25 J |
| 고정 100/100 | 964 | 114초 | 354 J |

제어기 동작 (마감 140초):

| 시각 | 상황 | 팬 조합 | 이유 |
| --- | --- | --- | --- |
| 0 ~ 134초 | 평소 PM 36 | 35/35 | 목표 구간 |
| 134초 | PM 50 초과 후 2초 | 100/60 | PM이 오르는 중 |
| 250초 | PM 48까지 하강 | 35/35 | 회복 완료 |
| 360 ~ 375초 | 센서 15초 끊김 | 100/100 (370초부터) | 센서 이상 안전 조합 |
| 386초 | 센서 복귀 | 35/35 | 정상 복귀 |

센서 값이 1초, 10초 빠진 경우는 직전 조합을 유지했고, 15초 이상 이어질 때만 안전 조합으로 갔습니다.

## 3. 시험 B: 젯슨 실행 로그 분석 (규칙형 제어)

팀원이 젯슨에서 실행한 로그(`energy_live_20261018_151402.csv`)입니다. 이 로그는 모델 제어기가 아니라 PM 기준값으로 단계를 나누는 규칙형 제어의 기록입니다(`reason`이 `pm_stage_*`).

| 항목 | 값 |
| --- | --- |
| 기록 길이 | 약 616초 (308행, 2초 간격) |
| 평소 PM | 32 ~ 35 |
| 연기 감지 (PM 50 초과) | 133초 |
| 최고 PM | 1188 (157초) |
| 팬 단계 | 35/35 → 60/60 (133초) → 100/100 (137초) → 60/60 (229초) → 35/35 (261초) |
| PM 500 → 50 소요 | 52초 (191초 → 243초) |
| 연기 구간(133~261초) 추정 에너지 | 약 218 J |
| 전체 추정 에너지 | 317.7 J |

관찰: PM이 올라오는 동안 팬이 단계적으로 올라가고 내려오는 동안 단계적으로 내려갔습니다. 433초에 센서 값이 한 번 비자 12초 동안 100/100으로 가서 약 25 J가 더 쓰였습니다. 이 구간은 모델 제어기에서 고친 문제입니다.

PM500 → 50 구간의 모델 예상(100/100 약 48초, 60/60 약 60초)과 이 기록의 52초(100/100과 60/60 혼합)는 비슷했습니다. 한 번의 관찰이라 성능 평가는 아닙니다.

## 4. 테스트로 찾아 고친 문제

| 문제 | 원인 | 조치 |
| --- | --- | --- |
| 연기가 한참 올라온 뒤에야 팬이 올라감 | 현재 PM만 보고 "마감 안에 35/35로 내려간다"고 판단해, 오르는 중에는 약하게 둠 | PM이 뚜렷하게 오르는 중이면 즉시 가장 빠른 조합 |
| 측정값 500 초과를 구분하지 못함 | 제어기가 PM을 500으로 잘라서 봄 | 500 초과는 "농도 불명"으로 보고 가장 빠른 조합 |
| 로그와 대시보드에 500까지만 표시 | 로그에 자른 값을 기록했고, 그래프 세로축도 500 고정 | 로그에 원본 값 기록, 그래프 축 자동 확장 |
| 센서 값이 한 번 빠지면 강강 | 한 번 누락도 즉시 안전 조합 | 10초 넘게 끊길 때만 안전 조합 |
| 마감이 프로그램 시작 시각부터 계산됨 | 상시 가동에서는 연기가 나중에 올 때 마감이 이미 지난 것으로 계산 | PM 50 초과 시점부터 계산 |

추가로, 이전 마감 시뮬레이션에서 시작 시각이 0초이면 경과 시간이 0으로 계산되던 오류도 고쳤습니다. 고친 뒤 마감 130 ~ 160초에서 9회 중 8회 달성으로 바뀌었습니다(이전 6 ~ 8회, 모델 안의 시뮬레이션).

## 5. 한계와 앞으로 확인할 것

- 모델 제어기를 실제 센서와 팬에 연결해 돌린 기록이 이 문서에 없습니다. 실행 로그가 나오면 시험 B와 같은 표로 추가합니다.
- 시험 A는 가상 환경이라, 실제 챔버에서 100/60이 100/100만큼 빠른지는 새 실험으로 확인해야 합니다.
- 에너지는 팬 사양과 RPM으로 계산한 추정값입니다. 전력계로 재면 `fan_power_rpm추정.csv`의 W만 바꾸면 됩니다.
- 이 방의 평소 PM이 35 안팎이라 목표 20에는 닿지 않습니다. 회복 판단은 PM 50 기준이고, PM20 도달을 지표로 쓰려면 목표값을 다시 정해야 합니다.
- 온도는 아직 제어에 쓰지 않습니다(담당 팀원 작업 후 통합).
- 마감 150 ~ 160초에서는 35/35와 60/35를 15초마다 오가는 경우가 있습니다.
- 새 표본(재실험 18회)으로 예측 오차, 마감 달성률, 고정 조합 대비 에너지를 평가해야 성능 수치로 쓸 수 있습니다.

## 시험 C: 젯슨 실기 실행 (10/20, 회귀 모델 제어기, 센서 PMS5003, 팬 4020 + ESP32 PWM)

기록: `젯슨실측_1020/energy_log_회귀모델_실측.csv` (356행, 약 356초, 1초 간격). 마감 140초, 9개 조합 비교, 1초 재계획, 연기 1회.

| 항목 | 값 |
| --- | --- |
| 평소 PM | 29 ~ 35 |
| 연기 감지(PM 50 초과) | 165.3초 (직전 45) |
| 팬 반응 | 같은 1초 안에 35/100으로 상승 (`pm_rising_fastest`) |
| 최고 PM | 404 (185.3초), 500 상한에는 닿지 않음 |

| 연기 구간(77초) 추정 에너지 | 약 92.7 J |

예측과 실측 비교 (35/100을 계속 쓴 구간, 각 PM 수준에서 PM50까지 걸린 시간):

| 출발 PM | 실측 | 회귀 예측 | 옛 시간표 예측 |
| --- | --- | --- | --- |
| 400 | 53.0초 | 45.8초 | 48.6초 |
| 300 | 44.0초 | 39.5초 | 41.4초 |
| 200 | 34.0초 | 31.1초 | 32.7초 |
| 150 | 29.0초 | 25.2초 | 26.6초 |
| 100 | 21.0초 | 16.6초 | 16.9초 |
| 75 | 14.0초 | 10.4초 | 10.2초 |

- 실기에서 제어기가 연기를 1초 안에 알아차려 팬을 올리고, PM 49에서 약약으로 내려오는 것이 확인되었습니다. 센서, 팬, 대시보드 연동도 동작했습니다.
- 두 예측 모두 실측보다 3~7초 짧게 나왔습니다(약 10~25%). 연기가 한 번뿐이고 최고 PM이 404로 챔버 실험(500 이상)과 조건이 다르므로, 지금은 "경향"으로만 읽어야 합니다.
- `deadline_unattainable_fastest`가 189초부터 나왔습니다. 꼬리(PM50→20) 시간 70초를 마감에서 빼는데 이 방은 PM이 20까지 내려가지 않아(배경 29~35) 마감을 실제보다 빡빡하게 계산한 것입니다. 이 설정에서는 마감 계산이 항상 "가장 빠른 조합"으로 쏠립니다.
- 같은 조건에서 고정 100/100, 고정 35/35 기록이 없어서 에너지 절감은 아직 말할 수 없습니다.
