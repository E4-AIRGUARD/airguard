# 온도 모델 Benchmark 결과 및 추가 측정 계획

작성 기준: 2026-10-22.

## 1. 현재 확보된 결과의 범위

온도 LSTM은 Jetson에서 센서·팬을 연결해 실제 실행한 기록이 있다. 그러나 온도 v6의 ONNX/TensorRT 변환 모델, 변환 후 출력 동등성 검증, 동일 조건의 최적화 전후 Latency·메모리 측정 결과는 아직 확보되지 않았다. 따라서 실행 이력을 속도 최적화 달성으로 표현하지 않는다.

이 문서는 ① 확보된 모델·제어 결과와 ② 추가 측정할 시스템 Benchmark를 구분한다. **모델 개선 전후 비교는 TensorRT 등 추론 최적화 전후 비교를 대체하지 않는다.**

## 2. FPS 대신 무엇을 측정하는가

온도 입력은 영상 프레임이 아니라 약 1Hz 센서 시계열이다. 영상 FPS를 온도 모듈에 그대로 적용하지 않는다. 추론 처리량은 calls/s 또는 windows/s로, 운전 성능은 전체 제어 tick의 처리시간과 1초 주기 준수율로 보고한다.

| 지표 | 온도 모듈의 정의 | 주의점 |
|---|---|---|
| 단일 추론 Latency | 준비된 8×10 입력의 모델 1회 forward 소요시간 | 전처리·후보 비교·DB·명령 통신 제외 여부 명시 |
| 후보 평가 Latency | 실제 운전과 동일한 6후보 예측 처리시간 | 후보 하나의 시간을 전체 제어 시간처럼 쓰지 않음 |
| 전체 tick Latency | 이력 준비→추론→정책→기록·명령 호출까지 | 포함 범위를 고정하고 명령 미전송 tick도 구분 |
| 장치 적용 지연 | 명령 송신→ESP32 피드백 변경까지 | 통신·기계적 팬 가속과 모델 계산 지연 구분 |
| 처리량 | 단위 시간당 추론 완료 수 | 1Hz 센서 생성률과 구분 |
| 마감 초과율 | 전체 tick이 1초를 초과한 비율 | 평균뿐 아니라 p95·p99·최대도 보고 |
| 메모리 | 프로세스 RSS, 전체 RAM, GPU 사용 시 장치 메모리 | pt 파일 크기를 실행 메모리로 쓰지 않음 |
| 정확도 유지 | 같은 입력에서 MAE·RMSE·FP·FN 변화 | 최적화 후 온도 오차와 경계 판정 변화 모두 확인 |

비전·연기 모델을 함께 실행하는 최종 통합에서는 영상 FPS도 별도로 기록한다. 온도 모듈의 tick 준수와 비전 FPS를 서로 다른 열로 보고한다.

## 3. 최적화 전후 결과표: 현재 상태

‘미측정’은 0이나 실패가 아니라 제출 가능한 측정값이 없다는 뜻이다.

| 실행 형식 | 변환·실행 상태 | 단일 추론 p50/p95 ms | 전체 tick p95 ms | 처리량 | RSS / GPU 메모리 | 공통 test 정확도 |
|---|---|---|---|---|---|---|
| PyTorch v6 CPU | 실제 운전 경로·장치 기록 존재 | 미측정 | 미측정 | 미측정 | 미측정 | 개발 평가 MAE 0.1758°C, FN 17; Jetson 동일 재평가 아님 |
| ONNX Runtime | 온도 v6 결과 미확보 | 미측정 | 미측정 | 미측정 | 미측정 | 미검증 |
| TensorRT FP16 | 온도 v6 결과 미확보 | 미측정 | 미측정 | 미측정 | 미측정 | 미검증 |
| TensorRT INT8 | 미수행, 필요성 판단 전 | 미측정 | 미측정 | 미측정 | 미측정 | 미검증 |

현재 수치로 속도 향상률·메모리 절감률·최적화 정확도 보존을 주장할 수 없다. 개발 평가 수치를 Jetson 최적화 검증값으로 복사하지 않는다. 연기 담당의 측정값도 온도 모델 결과로 사용하지 않는다.

## 4. 확보된 경량성 정보

| 항목 | 확인값 | 해석 |
|---|---|---|
| 입력 | 8표본 × 10특성 | 작은 시계열 입력 |
| LSTM 구조 | 1-layer, hidden 32 | 경량 신경망 구성 |
| 학습 파라미터 | 5,764개 | 복잡도 참고값 |
| pt 파일 | 29,193 bytes, 약 28.5 KiB | 가중치 파일 크기, 실행 메모리 아님 |
| 추론 경로 | CPU 입력 텐서 | GPU 온도 추론 완료라고 표현하지 않음 |
| 제어 평가 | 현재 6개 PWM 후보 | 순차 평가이므로 단일 forward 외 비용 존재 |

작은 모델이라는 사실은 GPU/TensorRT가 반드시 더 빠르거나 최적화가 불필요함을 증명하지 않는다. 작은 입력에서는 전송·실행 호출 비용이 상대적으로 커질 수 있으므로 최종 선택은 실측으로 판단한다.

## 5. 모델·정책 변경에 대한 별도 성능 비교

### 5.1 개발 데이터 재생

| 항목 | v4 예측+v5 정책+상승률 보조 | v6 예측+v6 정책+상승률 보조 |
|---|---:|---:|
| 5초 예측 MAE | 0.0685°C | 0.1758°C |
| 5초 예측 RMSE | 0.2559°C | 0.3323°C |
| 끝점 FP / FN | 1 / 18 | 6 / 17 |
| 초과 전 첫 팬 상향 | 1/5 사건 | 3/5 사건 |
| 첫 상향 평균 signed 선행시간 | 0.199초 | 0.798초 |
| PWM 변경 | 14회 | 15회 |
| 무가열 팬 상향 | 0회 | 0회 |

v6는 낮은 예측 MAE를 얻기보다 조기 대응을 강화한 연구안이다. 모델과 정책을 함께 변경했으므로 효과를 LSTM 구조 하나에 귀속하지 않는다. 이 비교는 모델·제어 성능 비교이며 실행 속도 최적화 Benchmark가 아니다.

### 5.2 실제 Jetson 연결 시험

| 항목 | v4 | v5 가열 실행 | v6 |
|---|---:|---:|---:|
| 유효 관측시간 | 269초 | 327초 | 300초 |
| 최고 온도 | 30.02°C | 30.05°C | 29.90°C |
| 26°C 이상 시간 | 81초 | 86초 | 73초 |
| 초과 적분 | 97.96°C·s | 105.62°C·s | 98.07°C·s |
| PWM 변경 | 20회 | 8회 | 6회 |
| 평균 추정 전력 | 0.7155W | 0.5906W | 0.4281W |
| 누적 추정 에너지 | 0.05347Wh | 0.05364Wh | 0.03567Wh |
| 초과 전 팬 상향 | 2/2 사건 | 0/2 사건 | 2/2 사건 |

세 구성 모두 5초 예측·8표본·보조 ON으로 기록되었다. 구성별 가열 사건은 2건이지만 동일 조건 독립 반복 2회는 아니다. 초기 온도·가열시간·시험 길이가 달라 단순 비율로 에너지 절감률을 제시하지 않는다. 모든 구성에서 26°C 초과가 발생했다. v6의 두 사건 최초 상향은 원본 상승률 보조였으며 LSTM 단독 성과가 아니다.

추정 전력은 팬별 5×0.27×(RPM/7500)³ W를 합산하고 유효 시간 간격으로 적분했다. 전력계 실측값이 아니며 Jetson·ESP32·센서·카메라 전력은 제외한다. 당시 후보 선택은 이전 PWM³ 정책이므로 현재 RPM 기반 후보 정책의 실험 결과로 쓰지 않는다.

## 6. 동일 조건 Benchmark 절차 — 후속 측정 계획

### 6.1 측정 조건 고정

| 항목 | 기록·고정할 내용 |
|---|---|
| 보드 | 실제 Jetson 모델, RAM 용량, 저장장치 |
| 소프트웨어 | JetPack, CUDA, cuDNN, Python, PyTorch, ONNX Runtime/TensorRT 버전 |
| 전원·클럭 | nvpmodel, 클럭 고정 여부, 냉각·온도·스로틀링 |
| 모델 | SHA-256, 입력 shape, dtype, 모델 batch=1, 후보 수=6 |
| CPU | intra/inter-op 스레드 수, 다른 프로세스 |
| 동시 실행 | 온도 단독 / 비전·연기·대시보드·DB 동시 실행 |
| 입력 | 같은 저장 입력 윈도우를 같은 순서로 사용 |
| 통신 | 추론만 / dry-run tick / 실제 장치 tick을 구분 |

CPU 실행이 기준이므로 CUDA 미사용이면 GPU 관련 열은 ‘해당 없음’으로 기록한다. 보드 모델을 자료만 보고 확정하지 않고 실행 장비에서 확인한다.

### 6.2 권장 측정 설계

1. 모델 로딩시간과 최초 호출을 별도 측정한다.
2. 예비 기준으로 warm-up 100회 후 1,000회 이상 반복하고, 조건별 3회 이상 재실행한다. 이는 수행 결과가 아니라 제안 조건이다.
3. monotonic 고해상도 clock으로 p50·p95·p99·최대·평균을 집계한다. GPU 실행에서는 비동기 호출 종료를 동기화하거나 장치 이벤트로 실제 완료시간을 측정한다.
4. 단일 forward, 6후보 평가, 전체 tick을 따로 기록한다. 전처리·DB·시리얼 포함 여부를 결과표에 명시한다.
5. 모델 로딩 전후 RSS와 운전 중 최대 RSS, 전체 RAM, 장치 메모리의 기준·최대값을 수집한다. 비전 공유 메모리와 온도 프로세스를 구분한다.
6. 최종 통합 구성으로 최소 30분 예비 연속운전을 실시해 누락 tick, 1초 초과 tick, 예외·재연결·센서 공백을 기록한다.
7. 각 변환 형식의 동일 1,532입력에 대해 원본 출력 대비 최대·평균 차이와 실제 정답 기준 MAE·RMSE·FP·FN을 다시 계산한다. 26°C 경계에서 분류가 바뀐 사례를 별도 저장한다.
8. 출력 차이 허용범위와 정확도 손실 허용치는 결과 확인 전에 합의한다. 안전성이 필요한 프로젝트에서 임의 허용치를 사후 선택하지 않는다.

CPU용 스레드 조정, 추론 모드, 후보 batch 평가 등의 최적화를 먼저 대조할 수 있다. 변환이 필요하면 ONNX 출력 동등성부터 확인하고 TensorRT를 검토한다. INT8은 보정 데이터와 정확도 손실 검증 비용이 있으므로 필수 성과처럼 강제하지 않는다. batch 후보 평가의 속도와 최종 정책 일치 여부도 함께 확인해야 한다.

## 7. 제출용 결론

본 온도 모듈은 약 28.5 KiB의 소형 LSTM으로 Jetson에서 센서·팬 연계 동작을 확인했다. 다만 파일 크기는 실행 메모리나 지연시간을 의미하지 않으며, ONNX/TensorRT 최적화 전후의 성능 향상은 아직 측정되지 않았다. 현재 제출 범위는 모델 예측 지표와 실제 제어 기록이며, 실행 최적화 평가는 동일 입력·동일 장비·동일 동시 실행 조건에서 단일 추론, 전체 제어 주기, 메모리 및 정확도 보존을 함께 측정하는 후속 과제로 명시한다.
