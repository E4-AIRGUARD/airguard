# 팬 자동제어 젯슨 적용 방법 (하드웨어 담당용)

## 이 폴더가 하는 일
`run_on_jetson.py`가 1초마다 먼지센서 PM2.5를 읽고 → `fan_controller.py`가 흡기/배기 팬 조합(PWM 35/60/100 9가지)을 고르고 → 팬에 출력하고 → 추정 에너지를 `energy_log.csv`에 기록합니다. 대시보드가 이 CSV를 읽어 보여줍니다.
시간 예측 모델(`model.json`)은 옛 20회 + 10/18 18회 + 10/20, 10/21 젯슨 각 9회(3배 가중)로 만든 회귀 모델입니다(10/21 갱신). 에너지 계산의 RPM은 젯슨 텔레메트리 10/20과 10/21 세션 중앙값의 평균입니다. 외부 라이브러리 없이 파이썬 표준 라이브러리만으로 돌아갑니다.

## 채워야 할 곳: `run_on_jetson.py` 안의 함수 2개
1. `read_pm()` : 먼지센서에서 PM2.5 원시값(ug/m3, 숫자 하나)을 읽어 반환합니다. 읽기 실패면 `None`(또는 예외)을 반환하면 됩니다. 500이 넘는 값도 자르지 말고 그대로 반환하세요(제어기가 직접 처리합니다).
2. `set_fan(intake_pct, exhaust_pct)` : 흡기/배기 팬 PWM 듀티(%)를 출력합니다. 값은 35, 60, 100 중 하나입니다.

## 실행
```
python3 src/run_on_jetson.py --fake                 # 센서/팬 없이 루프만 확인 (가짜 PM)
python3 src/run_on_jetson.py                        # 센서 읽기+판단+로그만, 팬은 안 건드림(dry-run)
python3 src/run_on_jetson.py --live                 # 실제 팬 PWM 출력
옵션: --deadline 70  PM이 500 아래로 내려온 뒤 PM50 아래까지 허용 시간(초), 0이면 항상 35/35
      --range-pm 50   PM이 이 값 이하면 범위 안으로 보고 35/35 유지(방 배경 PM이 50보다 높으면 올리세요)
      --interval 1    제어기 재계획 주기(초)    --prune  후보를 3단계로 제한
      --log energy_log.csv   --period 1.0       센서 읽는 주기(초)
```
Ctrl+C로 끝내면 `--live`에서는 팬을 100/100으로 두고 종료합니다.

## 대시보드
```
cd dashboard
python3 serve_dashboard.py ../energy_log.csv 8080
브라우저: http://<젯슨IP>:8080
```
- `dashboard.html` 파일을 더블클릭해서 열면 데모 데이터로 보입니다(화면 위에 "가상 데이터" 또는 "데모" 표시). 실시간 값을 보려면 반드시 `serve_dashboard.py`를 실행하고 `http://<젯슨IP>:8080`으로 접속하세요. 로그 경로는 `run_on_jetson.py --log`로 준 경로와 같아야 하고, `run_on_jetson.py`를 다시 시작하면 그 로그는 새로 덮어쓰입니다.
`python3 run_virtual_live.py`를 실행하면 실제 센서 없이 가상 연기 상황을 실시간으로 재생해 대시보드를 미리 볼 수 있습니다.

## 통계 시간표 모델과 회귀 모델 비교하기
같은 조건(연기 양, 방, 마감 값)으로 두 모델을 번갈아 돌리고 로그를 따로 저장해 비교합니다.
```
python3 src/run_on_jetson.py --live --log log_회귀.csv                                   # 회귀(기본)
python3 src/run_on_jetson.py --live --model model_시간표_옛20회.json --log log_시간표.csv    # 통계 시간표
```
비교할 것: 연기 감지부터 PM50 아래까지 시간, 마감(기본 140초) 달성 여부, 추정 누적 에너지, 팬 조합 전환 횟수. 순서는 번갈아 가며(회귀, 시간표, 회귀, 시간표 ...) 같은 횟수로 해 주세요. 고정 100/100 로그도 한 번씩 같이 찍으면 기준이 됩니다.

## 메모
- 에너지 계산에 쓰는 RPM은 젯슨 텔레메트리 10/20, 10/21 세션 중앙값의 평균(35%: 2475, 60%: 4590/4230, 100%: 5805/6300 흡기/배기)입니다. 세션마다 약 10% 달라집니다. 전력계로 실측하면 `fan_power_rpm추정.csv`만 고치면 됩니다.
- 마감(`--deadline`)은 "PM이 500 아래로 내려온 시점부터 PM50 도달까지"의 시간입니다(팬을 PM500에서 켜도 연기가 더 올라가는 구간은 마감 시계에 넣지 않고 가장 빠른 조합으로 처리). 이 모델은 161행(10/18~10/21 전체: 옛 20회 + 10/18 + 10/20 + 10/21 + new_problem 필수·선택 + PM500 시작 9조합)으로 학습했습니다. 마감은 PM50 도달까지의 시간입니다(이전에는 PM20 도달 기준이라 꼬리 70초를 미리 뺐음). 기본 70초이고, 값을 키우면 더 약한 조합으로 천천히, 줄이면 더 센 조합으로 빠르게 내립니다.
- 온도 센서는 아직 제어에 쓰지 않습니다.


## 실시간 보정 (v161 + 보정)
제어기가 매초 "지금까지 쓴 조합으로 모델이 예상한 하강 시간"과 "실제 걸린 시간"의 비율(0.7~1.6)을 다시 계산해서, 방이 모델보다 느리게/빠르게 내려가면 남은 마감 시간을 그 비율로 나눠 계획을 다시 세웁니다. 500 아래로 내려온 뒤 PM75 초과 구간만 사용하며, 로그의 조합 변경 이유는 기존과 같습니다. 효과는 기존 측정 28회 모의 확인에서 PM50까지 남은 시간 예측 오차 평균 1~3초 감소 수준이며 실제 팬 제어 효과는 아직 측정 전입니다.

## 정체 구간·전환 횟수 (추가)
- 정체 감지: PM이 80 이하에서 20초 동안 5%도 안 내려가면(바닥값 근처) 팬을 세게 돌려도 소용없다고 보고 35/35로 낮춥니다(이유 `stalled_lowest_power`).
- 조합 변경 후 최소 유지 시간을 15초에서 25초로 늘려 잦은 전환을 줄였습니다(급상승·측정상한 초과는 예외).
- 모의 확인(실제 PM 기록을 제어기에 넣은 것)에서 조합 전환은 3~4회였고 실제 팬 제어 효과는 아직 측정 전입니다.
