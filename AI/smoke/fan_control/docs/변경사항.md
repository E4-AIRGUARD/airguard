# 변경사항 (이전 `팬제어_젯슨_실행파일_v161_보정_정체감지.zip` 대비)

## 제어 로직은 바뀌지 않음
`fan_controller.py`, `model.json`(161행 회귀), 판단 방식(마감 70초, 속도 보정, 정체 감지, 최소 유지 25초)은 이전 zip과 같다. 팬이 내는 결과는 그대로다.

## 새로 추가한 파일
| 파일 | 내용 |
|---|---|
| `smoke_fan.py` | 연기 제어를 `SmokeFan.step(pm)` 한 줄로 부르는 통합용 모듈. 온도 쪽과 합칠 때 `combine_max` 사용 (흡기·배기 각각 더 큰 값, 제안 규칙) |
| `integration_example.py` | 연기 + 온도를 한 루프에서 합치는 예제 (`--fake`로 확인 가능) |
| `event_recorder.py` | PM이 50을 넘은 순간부터 50 이하로 회복 확정(3초 유지)될 때까지를 이벤트로 로컬 대기열에 기록. 카테고리 저장(`pm25` / `temperature`) |
| `uploader.py` | 대기열을 MySQL(`e4_recovery_events`, `e4_recovery_samples`)로 UPSERT 업로드 |
| `schema.sql` | 팀 DB 문서의 이벤트·샘플 테이블 사본과, 카테고리 열 추가 ALTER(선택) |
| `통합_가이드.md` | 연결 방법, 합치는 규칙, 이벤트 DB 저장, 카테고리 설명 |
| `변경사항.md` | 이 파일 |

## 고친 파일
| 파일 | 바뀐 점 |
|---|---|
| `run_on_jetson.py` | 옵션 `--event-db 파일`, `--device-id 이름` 추가. 지정하면 이벤트를 기록하고 안 쓰면 이전과 똑같이 동작 |

## 폴더 구조
zip 안의 바깥 폴더 이름을 한글에서 영문(`fan_control_final`)으로 바꿨다(윈도우에서 폴더가 비어 보이던 문제 때문).

## 확인한 것과 못 한 것
- 가짜 PM으로 호출, 이벤트 시작·회복 확정, 카테고리 저장, 업로더 SQL 생성(가짜 연결)을 확인했다.
- 실제 Aiven DB 접속·업로드, 센서·팬 실물 연결, 온도 쪽 코드와 합친 시험은 하지 않았다.
- 온도·습도·RPM 열은 이 프로그램이 읽지 않아 비어 있다.

## 폴더 구조 정리 (GitHub용)
파일을 한 폴더에 두던 구조를 연기 이미지 모델 저장소(`smoke-detection-v4`)와 같은 틀로 나눴다: `src/`(제어기와 실행 스크립트), `training/`(회귀 학습), `models/`, `benchmarks/`(검증·가상 시험과 결과), `integrations/`(대시보드, DB, 온도 통합), `docs/`, `data/`, `tests/`. 코드 내용은 같고 파일 위치와 경로만 바뀌었다. 실행은 `python3 src/run_on_jetson.py`, 테스트는 `pytest`. 자세한 구조는 루트 README.md 참고.
