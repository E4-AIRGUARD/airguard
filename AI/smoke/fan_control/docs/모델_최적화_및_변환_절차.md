# 모델 최적화 및 변환 절차

## 1. TensorRT 적용 여부

| 항목 | 내용 |
|---|---|
| 모델 종류 | 회귀식(1/T = k0 + k1 s(in) + k2 s(out) + k3 s(in)s(out)), 신경망 아님 |
| 파라미터 | 5개 (k0~k3, h) + 조합별 전력·구간 형태 표 |
| 파일 크기 | `models/model.json` 약 10 KB |
| 추론 비용 | 제어 1회(예측 + 조합 계획) 약 0.07 ms (x86 컨테이너에서 측정, 젯슨 실측 아님) |
| TensorRT 변환 | 하지 않음 (변환할 신경망 가중치가 없음) |
| 병목 | 추론이 아니라 센서 주기(1초)와 공기가 바뀌는 시간 |

**요약**: TensorRT 대상이 아니고, 최적화는 모델 구조를 단순하게 하고 추론 시간을 무시할 수 있는 수준으로 만든 것으로 갈음한다.

## 2. 모델 생성·배포 절차 (변환에 해당하는 부분)

| 단계 | 작업 | 명령 / 파일 | 결과물 |
|---|---|---|---|
| 1 | 측정 데이터에서 PM500→PM50 도달시간 추출 | `data/arrival_times/*.csv` | 조합별 도달시간 행 |
| 2 | 옛 통계 시간표 준비 (구간 형태·기본값) | `models/model_시간표_옛20회.json` | 조합별 평균 시간표 |
| 3 | 회귀 학습 (h 격자 탐색, h ≥ 0.1) | `python3 training/fan_model_regression.py <CSV>[:가중치] ...` (`src`에서 실행 또는 `pip install -e .`) | `models/model.json` |
| 4 | 전력 계산 | `data/fan_power_rpm추정.csv` (RPM 기반, 5V x 0.27A x (RPM/7500)^3) | 조합별 power_w |
| 5 | 예측 확인 | `python3 benchmarks/validate.py` (`data/raw` 필요) | `benchmarks/results/*` |
| 6 | 젯슨에 복사 | `models/model.json`, `src/`, `src/run_on_jetson.py` | 젯슨에서 실행 |
| 7 | 실행 | `python3 src/run_on_jetson.py --live` | 팬 제어, 에너지 로그 |

**요약**: 학습은 PC에서 numpy로 하고, 젯슨에는 만들어진 `model.json`만 가져가서 표준 라이브러리로 실행한다. 젯슨에는 numpy도 필요 없다.

## 4. 최종 모델 값

| 항목 | 값 |
|---|---|
| 계수 (k0, k1, k2, k3) | -0.494, 0.5703, 0.5801, -0.6443 |
| 포화 정도 h | 0.10 |
| 예측 500→50 (초) | 35/100 46.6, 60/100 49.4, 100/35 49.6, 100/60 50.7, 100/100 51.5, 60/60 53.3, 35/60 57.7, 60/35 60.4, 35/35 90.4 |
| 오차 | PM100까지 약 2초, PM50까지 평균 8~10초(중앙값 2~3초) |

**요약**: 큰 경향(강/강 빠름, 약/약 느림)은 맞추고, 비슷한 조합끼리의 순위는 오차보다 차이가 작아 신뢰할 수 없다.
