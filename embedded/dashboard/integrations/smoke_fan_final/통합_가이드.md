# 연기 팬 제어 + 온도 팬 제어 통합 가이드

## 파일
| 파일 | 역할 |
|---|---|
| `smoke_fan.py` | 연기 제어를 함수 하나(`SmokeFan.step(pm)`)로 감싼 통합용 모듈. 센서·팬을 직접 만지지 않음 |
| `integration_example.py` | 연기 + 온도를 한 루프에서 합치는 예제 (`--fake`로 센서 없이 실행 가능) |
| `fan_controller.py`, `model.json` | 제어기 본체와 161행 회귀 모델 (수정 불필요) |
| `run_on_jetson.py` | 연기 제어만 단독으로 돌릴 때 (기존) |

## 연결 방법
1. 메인 루프에서 1초마다 `cmd = smoke.step(pm)` 호출. `pm`은 PM2.5 원시값이고 센서 오류면 `None`.
2. `cmd.intake`, `cmd.exhaust`는 연기 쪽이 요구하는 PWM(%)이며 35/60/100 중 하나.
3. 온도 쪽도 같은 형태 (흡기%, 배기%)로 요구값을 내면 `combine_max`로 합쳐서 `set_fan`에 한 번만 출력.

## 합치는 규칙 (제안, 팀 합의 필요)
- 흡기·배기 각각 두 요구 중 더 큰 값을 사용. 한쪽이 환기를 요구하는데 다른 쪽이 약하게 낮추는 일을 막기 위함.
- 연기 쪽은 평소(범위 안) 35/35를 요구하므로, 온도가 요구가 없을 때는 `(35, 35)`를 넘기면 됨.
- 단점: 둘 다 동시에 켜지면 에너지 절감 효과가 줄어듦. 온도 쪽 선택 규칙을 몰라서 이 부분은 합의가 필요함.

## 알아둘 점
- 연기 쪽 판단 주기 1초, 조합을 바꾼 뒤 최소 25초 유지(급상승·측정 상한 초과로 세게 올릴 때만 예외). 합칠 때 온도 쪽이 자주 바뀌면 출력은 합쳐진 값이라 더 자주 바뀔 수 있음.
- 센서 값이 10초 넘게 안 들어오면 연기 쪽이 100/100을 요구 (`sensor_invalid_or_stale`).
- 기본값: 마감 70초(PM이 500 아래로 내려온 뒤 PM50까지), 범위 PM50 이하는 35/35. `SmokeFan(deadline_s=..., range_pm=...)`으로 바꿈.
- 에너지는 RPM 기반 추정이고, 온도 쪽 식((in/100)^3 + (out/100)^3 x 시간)과 가정이 달라 숫자를 바로 더하면 안 됨. 같은 식으로 맞춰 비교해야 함.
- 이 통합 루프는 센서·팬 실물로 시험하지 않았고, 가짜 PM으로 호출이 되는 것만 확인함.
