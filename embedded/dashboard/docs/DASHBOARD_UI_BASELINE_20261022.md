## 2. 실제 이상·회복 기록 그래프 수정

기존 실측 상세는 사건 종류와 관계없이 PM2.5·온도·습도 그래프를 출력했습니다. 이제 사건 카테고리에 따라 다음과 같이 표시합니다.

| 저장 카테고리 | 표시 그래프 |
| --- | --- |
| `pm25` | PM2.5 회복 추이 + 팬 전력 소모 |
| `temperature` | 온도 회복 추이 + 팬 전력 소모 |
| `combined` | PM2.5 회복 추이 + 온도 회복 추이 + 팬 전력 소모 |
| `unknown` / 항목 미기록 | PM2.5·온도 추이와 팬 전력 소모를 함께 표시하고 항목 미기록 상태를 유지 |

습도는 전력 자리에 표시하지 않습니다. 저장된 습도 원본은 측정 표본 표와 CSV에서 확인할 수 있습니다.

전력은 사건 표본의 실제 `intake_rpm`, `exhaust_rpm`으로 계산한 **팬 2대 합산 추정 전력(W)**입니다.

```text
팬 1대 추정 전력 = 5 V × 0.27 A × (RPM / 7,500)³
합산 추정 전력 = 흡기 팬 추정 전력 + 배기 팬 추정 전력
```

- 기존 `integrations/handoff_v6/src/fan_power.py`의 모델과 같은 식입니다.
- 전력계 측정값이 아니며 센서·제어 보드 등 전체 시스템 소비 전력이 아닙니다.
- 양쪽 RPM 중 하나라도 누락·음수·비정상 값이면 해당 전력 표본은 빈 값입니다. 실제 0 RPM은 0 W로 계산합니다.
- PWM이나 습도를 이용해 누락된 RPM을 대신 채우지 않습니다.
- 유효 표본이 2개 미만이면 RPM 기록 부족 안내를 표시합니다. 결측과 2.5초 초과 기록 공백은 선으로 연결하지 않습니다.
- RPM이 저장되지 않은 과거 사건은 이번 화면 수정만으로 전력 그래프를 복원할 수 없습니다.

## 3. 예시 모드와 실제 센서 모드

`run.py`는 프로젝트의 `dist` 폴더를 제공합니다. 별도의 프런트엔드 빌드나 예시 화면을 실측 화면으로 다시 복사하는 작업은 필요하지 않습니다.

`dist/dashboard-boot.js`가 URL의 `demo=1` 여부로 실행 경로를 나눕니다.

| 모드 | 실행 경로와 데이터 |
| --- | --- |
| 예시 `?demo=1` | `app.js` 예시 데이터와 사진, `smoke-alert.js`, `demo-temperature.js`를 사용합니다. 센서·카메라·Aiven 조회 및 팬 연결 신호를 시작하지 않습니다. |
| 실측 `demo=1` 없음 | `live-measurements.js` → `temperature-integration.js` → `live-camera.js` → `smoke-alert.js` → `dashboard-lifecycle.js` → `recovery-history.js` 순서로 확장한 뒤 장비 연결을 시작합니다. |

두 모드가 공통 레이아웃 CSS를 사용합니다. 실제 센서 모드의 팬·카메라·기록 내용은 실제 수신 데이터와 저장 기록으로 바뀌며, 미수신 값을 예시 값으로 채우지 않습니다. `scenario=temperature`는 예시 모드 전용입니다.

### 센서 없이 화면 재확인

프로젝트 폴더에서 실행합니다. 이미 8093 미리보기 서버가 실행 중이면 기존 서버를 사용합니다.

```powershell
python -m http.server 8093 --bind 127.0.0.1 --directory dist
```

- 기본 화면: `http://127.0.0.1:8093/?demo=1#dashboard`
- 온도 이상 예시: `http://127.0.0.1:8093/?demo=1&scenario=temperature#dashboard`
- 기록 화면: `http://127.0.0.1:8093/?demo=1#events`

### 모든 센서를 연결한 뒤 실행

1. 현재 수정본이 저장된 프로젝트 폴더를 사용합니다. 다른 PC에서는 이 수정본 전체가 전달되어야 합니다. 이전 ZIP이나 변경 사항이 반영되지 않은 원격 복제본은 같은 화면을 보장하지 않습니다.
2. 기존 Jetson 센서·통합 제어 API(8095), 연기·카메라 API(8092), PM/온도 기록 업로더 상태를 확인합니다. 이미 실행 중인 USB·카메라 소유 프로세스를 중복 실행하지 않습니다.
3. Aiven 기록 조회에는 기존 `runtime/aiven/.env`, CA 인증서 및 DB 드라이버가 필요합니다. 접속 정보는 이 문서에 기록하지 않습니다. 환경이 없다면 [README의 Aiven 설정](../README.md)을 따릅니다.
4. 기존 Aiven 가상환경이 구성된 이 PC에서는 다음과 같이 화면 서버를 실행합니다. 이미 같은 프로젝트의 8091 서버가 실행 중이면 해당 서버를 사용합니다.

```powershell
runtime/aiven-venv/Scripts/python.exe run.py
```

필요한 패키지가 설치된 Python 환경에서는 `python run.py`도 사용할 수 있습니다. 기본 서버는 `127.0.0.1:8091`이며 실제 장비 화면 주소는 다음과 같습니다.

```text
http://127.0.0.1:8091/?smoke=http://100.106.99.75:8092&sensors=http://100.106.99.75:8095#dashboard
```

주소에 `demo=1`을 넣지 않습니다. 8093 정적 미리보기 서버는 실제 Aiven API와 팬 연결 프록시를 제공하지 않습니다. 현재 장비 CORS도 8091 출처에 맞춰져 있습니다.

장비 IP가 달라지면 `run.py --control-url http://JETSON_IP:8095`와 화면의 `smoke`, `sensors` 주소를 함께 맞춥니다. 자동 운전을 활성화하는 기존 PC의 `runtime/dashboard_lease.key`를 유지합니다. 키가 없는 PC는 조회용이며, 키를 Markdown·Git·`dist`에 넣지 않습니다. 탭 연결과 팬 정지 정책은 SSOT를 따릅니다.

화면을 새로고침하면 디스크의 수정본을 읽습니다. 이전 화면이 남으면 `Ctrl+F5`로 다시 읽습니다. `index.html`과 `dashboard-boot.js`의 변경 파일 캐시 버전도 갱신되어 있습니다.
