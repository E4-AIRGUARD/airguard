# 팬 9개 조합 열 실험

## 후속 냉각 기록 요청 (2026-10-05)

- 사용자는 각 300초 측정 후에도 해당 조합과 같은 PWM으로 냉각하면서 온도 변화와 소요 시간을 기록하도록 요청했다. 약/약 실험 후에는 35/35%, 약/중 후에는 35/60%를 사용한다.
- 후속 냉각은 본 실험 300초 CSV와 분리해 세션의 `cooling/<번호_조합>/cooling.csv`, `samples.jsonl`, `status.json`에 저장한다. 약/약부터 강/강까지 9개 조합 폴더를 만들되 미실행 조합에는 데이터 파일을 만들지 않는다. CSV 9개 칼럼은 유지하고 `Heat_Load=0`으로 기록한다. 사진은 저장하지 않는다.
- 정상 BME 표본에서 22~26℃가 3회 연속 확인되면 팬을 정지한다. 기준 도달 시간(`threshold_elapsed_sec`)과 팬 정지 확인까지 포함한 시간(`total_elapsed_sec`)을 구분하고, 정지 후 온도 조건도 다시 확인한다.
- 첫 회차 `cycle_20261005_170255_381919/01_intake_weak_exhaust_weak`는 요청 시점상 이미 팬을 정지한 뒤였다. 17:11:42 KST, 32.51℃에서 35/35% 냉각을 별도 시작했으므로 측정 종료부터 연속 냉각한 것으로 해석하지 않는다.
- 첫 회차의 이미 진행 중인 후속 냉각만 별도 실행기 `C:/airguard/tmp/cool_heat_combination.py`가 담당한다. 수정된 `measure_heat_cycle.py`는 다음 회차부터 300초 후 팬을 끊지 않고 같은 속도로 추가 냉각을 이어간다. 추가 냉각의 통신·BME·팬 오류 또는 3600초 제한 초과 시 중단하고 팬 정지를 확인한다.

## 최신 실행 방식 (2026-10-05): 정상 30초 → 고정 30초 가열 → 회복, 전체 300초

새 데이터는 `measure_heat_cycle.py`로 측정한다. **팬 가동과 함께 측정·촬영을 시작**하고,
처음 30초는 정상 상태를 기록한다. 30초가 되면 소리와 메시지를 듣고 사람이 드라이기로
**30초간 가열**한다. 가열 시작 지시 후 30초가 경과하면 PC에서 종료 알림음을 재생하고 드라이기 OFF 메시지를 출력한다. 사람이 이 신호를 듣고 드라이기를 끈다.
측정 시작 기준 정상 구간은 0~30초, 가열 지시 구간은 30~60초, 회복 구간은 60~300초다. 알림은 측정 프로세스의 경과 시간으로 실행하며 채팅 예약 작업에 의존하지 않는다. PC 소리가 들리는 상태여야 한다.
40℃ 도달은 상태와 이벤트에만 기록하며 소리·실시간 안내는 하지 않는다. 가열 종료 신호는
가열 지시 후30초 경과 알림으로 통일한다. 회복 중 처음40℃에 도달해도 기록만 남긴다.
40℃ 미도달이어도 회복을 기록한다.
남은 시간 동안 같은 팬 조합으로 회복을 기록한다. 정상·가열·회복을 합쳐 **총 300초**이며,
40℃ 도달 시 타이머를 다시 시작하거나 300초를 연장하지 않는다.

- 팬은 정상·가열·회복 모두 선택한 흡기/배기 속도로 유지한다. 시작 시 회전 상승 구간도 기록된다.
- 시작 전 최신 온도 22~26℃와 정상 온습도 값, 팬 정지를 확인한다. PM2.5는 시작 기준으로 사용하지 않는다.
- CSV의 9개 칼럼명과 순서는 그대로다. 정상·회복은 `Heat_Load=0`, 가열 지시 구간은 `1`이다.
  실제 드라이기 전원이나 사람이 반응한 시각을 측정한 값은 아니며, 실제 ON/OFF 시각은 미확인(null)으로 둔다.
- 온도·습도·팬 PWM/RPM·PM2.5를 전체 300초 동안 기록한다. PMS 값이 오래되었으면 PM2.5는 빈칸이다.
- **전체 300초 동안 사진을 1초 간격으로 저장**한다. 시작 조건 대기 중에는 사진·CSV를 기록하지 않는다.
- 별도 창을 열지 않는다. 가열 시작/종료 신호와 최종 완료 메시지는 실행 콘솔에 출력하고 알림음을 재생한다.
- 한 번 실행하면 한 조합의 300초 측정과 후속 냉각을 수행한다. 다음 조합은 사용자가 준비된 뒤 별도로 시작한다.
- 300초 측정·촬영 완료 알림과 후속 냉각 완료 알림을 구분한다. 냉각 기준 도달 후 팬을 정지하고 종료 온도 및 다음 시작 조건(22~26℃, 정상 온습도, 팬 정지) 충족 여부를 안내한다.
- 30초는 가열 지시 시간이며 실제 전원 ON/OFF를 측정한 값은 아니다. `heat_stop_reason`과
  `heating_instruction_duration_sec`, `recovery_start_elapsed_sec`를 상태 파일에 기록한다.
- 300초에 `measurement_complete=true`를 기록하고 `status=cooling`으로 전환한다. 팬 PWM은 유지한다.
  후속 냉각 기준 도달 후 팬 PWM/RPM 0을 확인하면 `status=complete`를 기록한다.
  `outcome`으로 `target_not_reached`(40℃ 미도달), `no_recovery_samples`(회복 표본 없음),
  `recovery_not_finished`(본 측정 300초 종료 시 22~26℃ 밖), `returned_to_start_range`(본 측정 종료 시 범위 복귀)를 구분한다.
  이 `outcome`과 별도로 후속 냉각 결과는 `cooling/<번호_조합>/status.json`에 기록한다.
  범위 복귀는 장시간 안정화나 실제 최고온도 포착을 보장하지 않는다.
- 카메라 오류, 온습도 오류, DATA 5초 이상 단절, 팬 응답 오류, Ctrl+C 또는 `STOP` 파일은 중단 처리한다.
  부분 데이터는 보존하며 드라이기 OFF를 안내한다. `stop_verified=false`이면 실제 팬 정지는 확인되지 않은 상태다.

프로젝트 루트 `C:\airguard`에서 약/약 한 조합을 시작하는 명령:

```powershell
python -X utf8 -u embedded/new_fan/new_fan_t/measure_heat_cycle.py --combination 1 --session-dir embedded/new_fan/new_fan_t/data/clean_air_fan_matrix/heat/<새_세션명>
```

조합 번호 1~9는 흡기/배기 약/약, 약/중, 약/강, 중/약, 중/중, 중/강, 강/약, 강/중, 강/강이다.
약 35%, 중 60%, 강 100%를 사용한다. 기본 장치는 COM7 및 카메라 1이며,
`--port`, `--camera-index`로 바꿀 수 있다.

기본 저장 위치는 `data/clean_air_fan_matrix/heat/cycle_<시각>/<번호_조합>/`이며,
조합 CSV, `images/`(JPG와 `images.jsonl`), `status.json`, `events.jsonl`을 남긴다.
9개 조합에 같은 `--session-dir <경로>`를 지정해야 하나의 세션 `cooling` 아래에 냉각 기록이 모인다.
가열 시간이 달랐던 첫 시험을 고정 30초 데이터로 취급하지 않는다. 고정 30초로 약/약을 다시 측정할 때는 새 세션을 사용한다.
중단한 `fixed5s_20261005_weak_restart` 세션은 사용자 요청으로 CSV 1개(111개 표본)와 사진 112장을 포함해 삭제했다. 다음 측정은 사용자의 명시적인 시작 요청 후 실행한다.
이미 존재하는 조합 폴더는 덮어쓰지 않는다.
해당 조합 폴더 또는 상위 세션 폴더에 `STOP` 파일을 만들면 중단한다.

이 방식은 아래의 **가열 완료 후 냉각만 300초** 방식과 구분한다. 과거 측정 파일은 변경하지 않는다.

## 이전 실행 방식 (2026-09-29): 창 없이 수동 가열 완료 후 측정

사용자 최종 변경에 따라 창과 카운트다운은 표시하지 않는다. 사용자가 스톱워치로 5초 가열한 뒤
채팅으로 완료를 알리면 `measure_heat_after_manual.py`로 해당 팬 조합의 냉각 구간 300초를 기록한다.
사진도 이 300초에만 저장한다. 이 방식의 CSV는 냉각 구간이며 `Heat_Load=0`이다.
가열 완료 메시지와 센서/카메라 준비 후 실제 측정 시작 사이에는 지연이 있으므로,
실제 드라이기 OFF 시각이나 최고온도를 측정했다고 해석하지 않는다. 시작 시각은 `status.json`에 남는다.
가열 전 확인한 22~26℃ 근거 파일을 `--preheat-check`로 남기고, 가열 후에는 이 온도 범위로
다시 식을 때까지 기다리지 않는다. PM2.5는 기록만 한다.

현재 수동 세션은 `data/clean_air_fan_matrix/heat/manual_20260929_224615/`이다.
아래 창·버튼 방식은 이전 실행 방식이며, 현재 요청에는 사용하지 않는다.

2026-09-29 사용자 확정. 기존 Phase 실험과 별도 실행 파일인
`measure_heat_matrix.py`를 사용한다.

- 순서(흡기/배기): 약/약, 약/중, 약/강, 중/약, 중/중, 중/강, 강/약, 강/중, 강/강.
- 약 35%, 중 60%, 강 100%. 모든 조합은 흡기·배기를 함께 가동한다.
- 환경 시작 조건은 온도 **22~26℃(경계 포함)**. 정상 온도 센서의 최신 값과 팬 정지도 확인한다.
- PM2.5는 기록만 한다. **17~20 기준은 이후 내부 연기 실험용**이며 기존 공통 실행 파일의 조건은 유지한다.
- 준비 버튼 → 준비 카운트다운 5초 → 팬 정지 상태에서 드라이기 5초 가열 →
  드라이기 OFF 신호와 함께 지정 팬 가동 → 300초 측정 → 팬 정지 확인 및 완료 표시.
- 다음 조합으로 자동 시작하지 않는다. 식힌 뒤 조건이 충족하면 사용자가 다시 준비 버튼을 누른다.
- 드라이기는 사람이 직접 켜고 끈다. `Heat_Load`는 화면의 5초 가열 지시 구간이며 실제 전원 피드백이 아니다.
- 사진은 **가열이 끝난 뒤 팬 측정 300초 중에만 1초마다** 저장한다.
  준비 카운트다운, 가열 5초, 조합 사이 냉각 대기에는 저장하지 않는다(사용자 최종 변경).
- 마지막 조합 완료 또는 전체 중단 시 촬영도 종료한다.

## 저장

`data/clean_air_fan_matrix/heat/<세션ID>/`

- `csv/01_intake_weak_exhaust_weak.csv` 등 조합별 CSV 9개: 가열 5초 + 팬 측정 300초.
- `images/`: 팬 측정 구간 JPG와 촬영 시각을 담은 `images.jsonl`.
- `events.jsonl`: 조합별 가열 시작, 가열 종료/팬 시작, 측정 종료, 팬 정지 확인 시각.
- `session.json`: 현재 상태·최근 센서·완료 목록·사진 수. 화면과 에이전트의 진행 확인용.
- 사진은 CSV의 `Time` 및 이벤트 시각으로 해당 조합과 연결한다. 대기 사진은 없다.
- CSV 칼럼은 기존 `Time,Temp,Humidity,Exhaust_PWM,Intake_PWM,Heat_Load,Exhaust_RPM,Intake_RPM,PM2.5` 그대로다.
- PMS 수신이 오래된 경우 PM2.5는 빈칸으로 저장한다. PM 농도나 PMS 지연으로 시작을 막지 않는다.
- 카메라 실패·센서 통신 중단·온도 오류·팬 응답 오류는 해당 조합 완료로 처리하지 않고 중단한다.

```powershell
python -X utf8 -u embedded/new_fan/new_fan_t/measure_heat_matrix.py
```
