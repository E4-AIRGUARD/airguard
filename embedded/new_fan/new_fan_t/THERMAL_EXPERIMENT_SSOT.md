## 팬 조합 — 약·중·강풍 3단계만 사용

실제 코드/배선에 있는 단계는 이 셋뿐이다: **약풍 35% · 중풍 60% · 강풍 100%**.

이번 실험에서 허용하는 조합은 아래 두 개로 고정한다. 둘 다 배기가 흡기보다 20%p 이상
높다. 35/100도 수치상 차이 조건은 만족하지만 이번 실험에서는 사용하지 않는다.
PWM 차이는 실험 제어 조건이며, 실제 음압 확보 여부는 별도 차압 측정이 필요하다.

| 조합 | 흡기 | 배기 | 차이 |
|---|---|---|---|
| A | 약풍 35% | 중풍 60% | 25%p |
| B | 중풍 60% | 강풍 100% | 40%p |

흡기단독·배기단독·둘 다 같은 속도는 `measure_thermal_response.py`에서 아예 실행이 막힌다.

## Phase 정의 (베이스라인 + 4단계 — 문 개방 외란 제외)

Phase1~3의 원래 목표온도는 45°C였으나, **드라이기 5초 가열로는 최대 약 39°C까지만
올라가는 게 실측 확인됨** — 이번 회차는 **드라이기 5초 가열 · 목표온도 38°C**로
진행한다. 45°C 도달을 위해 가열 시간을 늘리지 않는다. 5초가 되면 드라이기를 직접 끄고
`c`로 OFF를 표시한다(38°C 도달 알림이 먼저 오면 그때 끈다). 목표 미도달로 끝나면
냉각 단계 미실행으로 보고하며, 임의로 가열을 연장하지 않는다.

| Phase | 목적 | 팬 조합 | 명령 |
|---|---|---|---|
| 0 | 베이스라인 (팬·가열 없음) | 정지 | `measure_thermal_response.py phase0_baseline --duration-min 5 --intake 0 --exhaust 0` |
| 1 | 저속 냉각 | 조합 A (흡35/배60) | `... phase1_low --duration-min 15 --intake 35 --exhaust 60 --heat-until-temp 38` |
| 2 | 중속 냉각 | 조합 B (흡60/배100) | `... phase2_mid --duration-min 15 --intake 60 --exhaust 100 --heat-until-temp 38` |
| 3 | 조합 B 반복 측정 | Phase2와 동일한 조합 B·5초 가열, 관측 시간만 10분 | `... phase3_high --duration-min 10 --intake 60 --exhaust 100 --heat-until-temp 38` |
| 4 | 지속 가열 + 팬 평형 유지 | 조합 B | `... phase4_sustained --duration-min 15 --intake 60 --exhaust 100 --heat-from-start` |

Phase3은 더 강한 팬 단계가 아니다. Phase2와 관측 시간이 다르므로 냉각 성능 비교는
공통 시간 구간에서 한다. Phase4의 지속 가열은 5초 가열 회복과 별도 조건이며,
5초 가열 데이터로 지속 가열 평형을 검증했다고 해석하지 않는다.

**Phase 4에서 원래 계획했던 "문 10초 개방" 외란 투입은 이번 회차에서 물리적으로 불가능해서
뺐다** — 지속 가열 상태에서 팬이 평형을 유지하는지까지만 본다. 문을 열 수 있게 되면
`--event-at-min <분>:<메시지>` 옵션으로 다시 넣을 수 있다(스크립트에 이미 구현돼 있음).

## Heat_Load 기록 방식

드라이기는 수동 장치라 펌웨어가 알 수 없다 — `measure_thermal_response.py` 실행 중
키보드로 사람이 표시한다: `h`=ON(1) · `c`=OFF(0) · `q`=조기종료.
`--heat-until-temp` 모드는 목표온도 도달을 스크립트가 감지해서 Heat_Load를 자동으로
0으로 바꾸고 지정한 흡기/배기 값을 곧바로 적용한다. 이는 기록·팬 제어만 수행하며
드라이기 전원을 끄지는 않는다. 실제 OFF는 사람이 수행한다. `--heat-from-start` 모드는 처음부터
지정한 흡기/배기로 팬을 돌리고 Heat_Load는 계속 키보드로 사람이 관리한다(Phase4용).

## Jetson 연동 펌웨어 (T08_cleanbox_fw.ino)

핀맵은 `new_fan_t.ino`와 동일하게 통일: 팬PWM 13/19, Tach 5/33, BME280 SDA21/SCL23,
PMS5003 RX14/TX27. 가열패드·부저·LED는 배선하지 않기로 해서 관련 코드는 전부 제거했다.

- 출력: 1초마다 JSON 두 줄(`{"k":"sens",...}`, `{"k":"stat",...}`)
- 입력: `C <흡기%> <배기%>` (가열 인자 없음, 유효시간 3초) · `T <pm25>` (시험용 PM 주입) ·
  `E <type> [note]` (실험 이벤트 마커)
- 안전 우선순위: LIMIT(센서 이상·과열) > DANGER(PM 매우 높음) > WARNING(PM 높음) >
  Jetson 명령 > LOCAL(명령 없음 시 최소 순환)
- Jetson 쪽 확인용 스크립트: `embedded/jetson/cb_serial_check.py` (같은 명령 형식으로 갱신됨)

## 측정 코드 보완 (2026-09-28)

- 허용 명령 조합을 정지 0/0, A 35/60, B 60/100으로 제한한다.
- 유한한 양수 측정 시간, 유한한 목표온도, 이벤트 형식을 시리얼 연결 전에 검증한다.
- BME 오류 또는 NaN/Inf 온도는 냉각 전환에 사용하지 않는다. 무효 온습도는 CSV 빈칸으로 기록한다.
- 고정 9컬럼 CSV를 매 샘플마다 저장한다. 통신 실패 시에도 이미 기록한 행은 남긴다.
- 종료 시 팬 정지 명령을 시도하고 포트를 닫는다. 전송 실패는 명확히 알리며 정지 성공으로 간주하지 않는다.
- 기본 포트는 COM7이며 `--port`로 변경할 수 있다. 이 스크립트는 `DATA,...`를 출력하는
  `new_fan_t.ino` 전용이다. T08의 JSON/C 프로토콜과 호환되지 않는다.
- `--duration-min`은 가열 대기를 포함한 전체 측정 시간이다. 목표온도 미도달 또는
  유효 형식의 DATA 행이 하나도 없는 측정은 정상 완료로 처리하지 않는다.
- `h/c/q` 입력은 Windows 콘솔에서 지원한다. 비대화형 실행에서는 직접 키 입력할 수 없다.

회귀 검증(장비 연결 없이 모의 시리얼 사용):

```powershell
python -m unittest discover -s embedded/new_fan/new_fan_t -p "test_*.py" -v
```


## 카메라 사진 기록

기본 카메라 인덱스는 1, 저장 간격은 1초다. 센서 측정과 별도 스레드에서 프레임을 계속 읽고
JPG를 저장한다. 열 실험 사진은 `data/thermal_images/<phase>/<실행ID>/`에 모인다.
같은 Phase를 다시 실행해도 새 폴더를 만들며 기존 이미지는 덮어쓰지 않는다.

- 파일명: `000001_YYYYMMDD_HHMMSS_ffffff.jpg` (순번 + PC 수신 시각)
- `images.jsonl`: 각 이미지의 PC 수신 시각(`Time`)과 측정 시작 후 경과 초
- `run.json`: 해당 실행의 센서 CSV 경로·팬 조합·카메라 설정
- 센서 CSV의 9컬럼은 유지한다. 사진과 센서는 PC 시각으로 비교하며, 하드웨어 동기화는 아니다.
- 첫 사진은 측정 시작 후 첫 프레임이다. 이후 1초 목표 일정으로 저장하며 드라이버·디스크
  지연에 따라 실제 촬영 시각과 장수는 조금 달라질 수 있다.
- 카메라 열기·수신·저장 실패 시 오류를 보고하고 측정을 종료한다. 이미 저장한 CSV·사진은 남긴다.

`--camera-index`, `--image-interval-sec`, `--image-dir`로 설정을 바꿀 수 있다.
센서만 점검하려면 `--no-camera`를 지정한다.

## 공통 시작 조건 (2026-09-29 추가)

매 Phase와 매 팬 조합의 센서 기록·사진 저장을 시작하기 직전에, **같은 DATA 샘플**에서
아래 조건을 모두 확인한다. 경계값은 포함한다.

- PM2.5: **17 이상 20 이하**
- 온도: **22°C 이상 26°C 이하**
- BME280 오류 없음(`bme_err=0`), PMS5003 갱신 지연 없음(`pms_stale=0`)
- 온도·PM 값이 유효한 수치일 것(NaN/Inf·잘못된 DATA는 통과 불가)

조건을 만족하는 유효 샘플을 받으면 기존 팬 명령을 적용하고 센서 CSV 기록·카메라 JPG 저장·
측정 타이머를 시작한다. 추가 연속 유지 시간을 임의로 넣지 않는다. 범위 밖이거나 수신이
없으면 통과할 때까지 대기하며, `q`·Ctrl+C·STOP 파일로 취소할 수 있다.

대기 중에는 시작 판단용 센서 수신과 카메라 준비만 수행한다. **CSV 행과 JPG는 저장하지
않고 대기 시간을 측정 시간에 넣지 않는다.** 별도 환기 동작이나 팬 조합 변경은 추가하지 않는다.
시작 시 확인한 값·시각·대기 시간은 CSV 옆 `<실행ID>.start_check.json`에 별도로 남긴다.

연기 투입이나 드라이기 5초 가열은 시작 조건 확인 후 기존 실험 절차대로 수행한다.
**시작 후 온도나 PM2.5가 범위를 벗어나는 것은 실험 데이터이므로 기록·촬영을 중단하지 않는다.**
열 실험의 38°C 냉각 전환, 팬 조합 순서, 측정 시간, 사진 1초 간격, CSV 9컬럼명·순서는 유지한다.

이 조건은 공통 측정 함수에 적용되어 열 실험, 무가열 9조합, Phase0에서 각각 확인된다.
기존 2026-09-28 데이터에는 소급 적용하지 않는다. 현재 변경은 시작 전 조건 확인만 추가하며,
새로운 연기 생성 절차나 자동 환기 절차를 정의하지 않는다.
