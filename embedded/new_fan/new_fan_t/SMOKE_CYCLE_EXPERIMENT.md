# 실시간 확인 및 연기 투입·회복 실험 (2026-10-08 검토 반영)

기존 2026-10-01의 300초 실험과 별개인 새 프로토콜이다. 기존 데이터와 코드는 유지한다.
현재 권장 예비 절차는 **정상 팬 가동 10초 → 양쪽 팬 OFF 확인 → 짧은 연기 투입
(`--smoke-sec` 명시) → 제거 확인 → 해당 팬 조합으로 즉시 환기 → PM2.5 ≤20 종료**이다.
`--smoke-fans-off`를 반드시 사용한다. 인수를 생략하면 과거의 60초 투입·제거 후 OFF 30초 방식이므로 주의한다.
피크 목표와 분석 구간은 아래의 임시 기준이며 실제 장비에서 검증된 최적값이 아니다.
고농도 경고가 나도 자동 제거되지는 않는다. 발생원 제거는 수동이고, 기록은 회복 또는 시간 제한까지 계속된다.
현재 코드는 환기 시작 후 **최소 10초 관측**, **2개 연속 DATA에서 설정 PWM·양쪽 RPM>0 확인**,
**새 PMS 표본 3개 연속 ≤20**을 모두 만족한 뒤 종료한다. 센서 반응이 늦는 짧은 투입에서 조기 종료를 줄이기 위한 조건이다.
이 10초는 팬을 끄고 기다리는 시간이 아니다. 제거 직후부터 팬은 계속 가동한다.

## 1. 먼저 실시간 확인만 하기

2026-10-08 추가: BME280 비활성화 상태의 2초 수동 투입 9조합 탐색 측정은
`--smoke-sec 2 --manual-smoke --smoke-fans-off --no-environment`를 함께 사용한다.
`--no-environment`는 새 CSV의 온도·습도·기압 컬럼을 제외한다(기압은 기존 CSV에도 없었다).
CSV는 `Time,Exhaust_PWM,Intake_PWM,Heat_Load,Exhaust_RPM,Intake_RPM,PM2.5`를 저장한다.
기존 측정 파일은 변경하지 않는다. 상한 초과 판정은 유지하며, 2초는 작업자 수동 목표 시간이다.

### 2026-10-08 탐색 측정 완료 기록

`data/clean_air_fan_matrix/smoke_manual2_matrix/20261008_152756/matrix_plan.json`에
무작위 실행 순서, 조합별 최종 기록, 이전 시도와 재측정 이력을 보존했다.
9개 조합 모두 완료·팬 정지 확인 기록을 확보했지만, 최종 회차 모두 임시 상한 500을
초과했다. 이는 **유효 27회 본 실험의 완료가 아닌 탐색 측정 1블록**이다.
8·9회차는 작업자 요청으로 다시 측정했으며 먼저 완료한 기록도 유지한다.
4회차는 배기 배선 이탈과 종료 팬 확인 오류, 6회차 첫 시도는 카메라 프레임 수신 실패로
제외하고 새 폴더에서 재측정했다. 실패 회차를 정상 완료 자료와 합치지 않는다.

수동 투입에서는 `inserted` 입력 없이 `removed`를 받을 수 있다. 이때 2초는 작업자가
잰 목표 시간이며 `actual_smoke_sec`는 `null`이다. 제거 확인 시각은 채팅·명령 전달 지연을
포함하므로 실제 물리적 제거 시각으로 간주하지 않는다. 종료까지 걸린 시간은 운영 기록이며
팬 성능 비교 지표가 아니다. 원본 사진은 기존 `.gitignore` 규칙대로 로컬에 보존하고,
센서 CSV·PMS 표본·촬영 시각 목록·상태와 이벤트 로그는 Git으로 추적한다.

### BME280 연결 및 진단 상태

소스 기본값은 `ENABLE_BME280=0`이며 SDA는 GPIO 25, SCL은 GPIO 26이다.
2026-10-08 별도 진단 빌드에서 BME280을 활성화했으나 기존 센서와 예비 4핀 센서 모두
0x76·0x77 주소에 ACK가 없었다. 칩 ID·온습도·기압은 검증하지 못했으며, 특정 신호선이나
센서 자체 고장으로 원인을 확정하지 않았다. 상세 로그는 `data/sensor_checks/`에 있다.
마지막 장치 검사는 BME280 활성화 진단 빌드로 수행했으므로, 장치에 올라간 펌웨어와
저장소 기본값은 다를 수 있다. 다음 실험 전에 연결과 펌웨어 설정을 다시 확인한다.
원시 DATA의 `-99`는 측정값이 아닌 오류/비활성화 표시다.

프로젝트 루트 `C:\airguard`에서:

```powershell
python -X utf8 embedded/new_fan/new_fan_t/monitor_pms5003.py --port COM7
```

PM2.5 숫자, 최근 120초 그래프, 수신 지연/오류를 창에 표시한다. 팬 제어 명령,
사진 촬영, 파일 기록, 목표 도달 알림은 없다. 창을 닫으면 PC 시리얼 연결을 해제한다.
이는 ESP32 전원 종료가 아니다. USB 시리얼 드라이버에 따라 포트 개방 시 보드가
재시작될 가능성이 있어 DTR/RTS는 비활성화하지만 무재시작을 보장하지 않는다.
다른 센서 프로그램과 COM 포트를 동시에 열지 않는다. 카메라 미리보기는 동시 사용 가능하지만
본 측정 시작 전에는 종료해 녹화 프로그램에 카메라를 넘겨준다.
`--fan-duty 35`를 모니터 명령에 추가하면 약/약을 가동하고 창을 닫을 때 정지한다.

창 없이 콘솔에서 확인하려면:

```powershell
python -X utf8 embedded/new_fan/new_fan_t/measure_smoke_cycle.py --mode monitor --port COM7
```

`quit` 입력 후 Enter로 종료한다. 기본 모드는 monitor라 실험이 자동 시작되지 않는다.

## 2. 실험 시작 전 필요한 펌웨어

기존 펌웨어는 1초마다 캐시된 PM을 DATA로 출력하므로 GUI/콘솔 표시만 가능하다.
실험에는 수정된 `new_fan_t.ino` 업로드가 필요하다. 체크섬·프레임 길이·오류 코드가
정상인 PMS 수신마다 다음 줄을 추가로 출력한다:

```text
PMS_SAMPLE,sequence,esp32_millis,PM1_atmospheric,PM2.5_atmospheric,PM10_atmospheric
```

기존 DATA 13필드와 센서 CSV 9칼럼은 변경하지 않았다. PMS 수신 전의 초기 0은
이제 stale로 표시한다. 실험 시작·회복 판정은 DATA 반복값이 아닌 새 PMS 수신 번호로
수행한다. ESP32 재부팅/카운터 역전, 통신 단절을 정상 완료로 처리하지 않는다.

## 3. 한 조합 실행

### 2026-10-07 두 번째 실험: 연기 생성 중 팬 OFF, 제거 후 즉시 환기

```powershell
python -X utf8 embedded/new_fan/new_fan_t/measure_smoke_cycle.py --mode experiment --port COM7 --combination 1 --smoke-fans-off --camera-manual-exposure -6 --out-root embedded/new_fan/new_fan_t/data/clean_air_fan_matrix/smoke_fan_recovery
```

매회 시작 전에 새로운 PMS 표본 3개 연속 PM2.5 ≤20을 확인한다. 온도는 기록하되 시작 조건에서 제외한다.
정상 10초 동안 해당 팬 조합을 가동하고, 양쪽 PWM/RPM 0을 2개 DATA에서 확인한 뒤 연기 투입을 안내한다.
사용자의 실제 투입 확인(`inserted`)부터 60초 동안 팬을 끈 채 기록한다. 제거 안내 후 사용자의 제거 확인(`removed`)이 들어오면
추가 OFF 대기 없이 같은 조합으로 환기를 시작한다. 환기 시작 이후 새로운 PMS 표본 3개 연속 PM2.5 ≤20이면 기록을 끝내고 팬을 정지한다.
위 내용은 당시 방식이며, 현재 코드에는 문서 첫머리의 최소 관측·팬 재가동 확인 조건이 추가돼 있다.
사진은 전체 정상·팬 정지·투입 대기·생성·제거 대기·환기 구간에 1초 간격으로 저장한다. 센서 CSV 칼럼은 그대로 유지한다.
실험 전 기준을 맞추기 위한 강/강 환기는 별도 준비 작업으로, 이 실험의 CSV·사진에 포함하지 않는다.
약/약 회차의 본 환기는 반드시 35%/35%를 유지한다. 다른 조합도 각 회차의 설정 속도를 유지한다.

  다만 PM은 누적 크기 구간이므로 작은 입자가 지배하면 서로 비슷하거나 같을 수 있다.
  값의 일치만으로 실제로 불가능한 측정이라고 단정하거나, 급락의 원인을 포화 해제로 확정하지 않는다.

  체크섬 통과는 전송 무결성 검사이며, 센서 내부 처리·보정·설치 영향이나 모든 펌웨어 오류를 배제하지 않는다.

- 제조사 매뉴얼의 **CF=1 PM2.5 유효 범위 0~500, 최대 출력 범위 ≥1000**에서
  `≥1000`은 출력 상한이 1000이거나 그 지점에서 포화된다는 뜻이 아니다.
  현재 로그는 **대기환경용 data5**이고 사양의 대상은 **CF=1 data2**다.
  500 이하도 이 연기의 절대 질량농도가 정확하다고 보장할 수 없다.
- 6회 모두 300→150의 로그 공간 R²≥0.998이라는 계산은 재현됐다.

  300 위의 둔화 원인이 혼합인지, 100 아래의 둔화 원인이 방 공기인지 현 자료만으로 분리할 수 없다.
  종료 직전 상자 표시값 약 20은 방 공기를 독립 측정한 값이 아니며, 종료 조건 자체의 영향도 받는다.

### 예비 실험: 투입 시간 결정 (임시 목표 표시값 400±50)

기존 700±100은 고농도 노출을 피하려는 목적에 비해 높아 **400±50(350~450)**으로 낮춘다.
표시값 500을 보수적인 **실험 상한**으로 정했으며 센서의 실제 포화점 또는 정확도 보증 범위라는 뜻은 아니다.
이 목표로 300→150 구간이 충분히 확보되는지는 아직 검증하지 않았다.

1. 팬을 끈 채 약/약(조합 1)에서 **2초 같은 짧은 투입부터** 시작하고 각 조건을 반복한다.
   낮을 때만 조금씩 늘린다. 5·8·10초를 모두 반드시 시험하지 않는다. 시간과 연기량이 비례한다고 가정하지 않는다.
2. 350~450을 목표로 하고, 회차 어느 단계든 500 초과 또는 포화 의심이 있으면 본 비교에서 제외한다.
   실제 확인 간격과 `removal_delay_after_nominal_sec`를 확인한다. 수동 지연이 크면 짧은 투입시간 실험 자체가 성립하지 않는다.
3. 같은 투입 방식으로 강/강(09)을 포함한 다른 조합을 예비 측정한다. 발생원 위치·온도·발생량,
   개구부 개방 방식, 센서 위치, 시작 PM·온습도, 외부 공기 조건을 일정하게 기록한다.
4. 환기 시작 후 300 위에서 150 아래까지 내려가는 구간을 실제로 관측해야 한다.
   전체 피크 하나로 구간 확보를 판정하지 않는다. 시간/표본 수가 부족하면 분석창·투입 방식을 다시 설계한다.
   팬 OFF 투입 중에는 조합별 팬 설정이 적용되지 않으므로 01이 항상 최고 피크, 09가 항상 최저 피크라는 보장은 없다.

```powershell
python -X utf8 embedded/new_fan/new_fan_t/measure_smoke_cycle.py --mode experiment --port COM7 --combination 1 --smoke-fans-off --smoke-sec 2 --camera-manual-exposure -6 --out-root embedded/new_fan/new_fan_t/data/clean_air_fan_matrix/smoke_dose_pilot
```

- `--smoke-sec`: `inserted` 확인부터 제거 안내까지의 초(0 초과 120 이하, 기본 60).
  실제 투입 시간은 `removed` 입력까지라 `status.json`의 `actual_smoke_sec`로 확인한다. 안내 직후 바로 제거한다.
- 사용자가 직접 시간을 재고 채팅으로 제거만 알리는 경우 `--manual-smoke`를 함께 사용한다.
  이 모드는 투입 안내 뒤 `inserted` 없이 `removed`만 받아 즉시 환기할 수 있다.
  프로그램이 투입 시각을 관측하지 않았으므로 `actual_smoke_sec=null`, `dose_timing_mode=operator_manual`을 기록한다.
  `smoke_sec`는 사용자가 맞추기로 한 목표 시간일 뿐 자동으로 측정한 실제 노출시간이 아니다.
  채팅 전달 지연은 물리적 제거~환기 시작 지연에 포함된다. 엄밀한 시간 비교에는 현장 입력/자동 제어가 필요하다.
- 예상보다 연기가 많아 먼저 제거했다면 안내 전에도 `removed`를 입력할 수 있다. 즉시 환기로 넘어가고
  실제 확인 간격과 `removed_before_nominal=true`를 기록한다. 예정 시간만큼 투입한 회차로 취급하지 않는다.
- `removal_prompt_lateness_sec`는 예정 시각 대비 프로그램 제거 안내 지연,
  `removal_delay_after_nominal_sec`는 예정 시각 대비 제거 확인 지연이다. 두 값을 함께 확인한다.
- PM2.5가 실험 상한 500을 넘으면 `pm_over_limit`, 높은 세 값 일치가 감지되면 `pm_suspected_saturation` 경고와 이벤트를 남긴다.
  측정은 회복(≤20)까지 계속한다. 다음 회차를 깨끗한 상태로 시작하기 위해서다.
- `status.json`에 `peak_pm25`(관측 최고값), `peak_within_limit_pm25`(상한 이내 표본만의 최고값),
  `suspected_saturation`, `over_limit`, `peak_verdict`를 기록한다. `peak_valid_pm25`라는 오해 소지가 있는 이름은 제거했다.
  새 로그의 정책은 `quality_policy=atmospheric_pilot_v2`다. 기존 원시 로그와 status는 수정하지 않는다.

| peak_verdict | 조건 | 조치 |
|---|---|---|
| `target` | 350~450 | 반복성과 회복 구간을 확인한 뒤 채택 후보 |
| `below_target` | 301~349 | 여유 부족; 분석 가능 여부는 회복 구간으로 판단 |
| `above_target` | 451~500 | 투입량 줄이기 검토 |
| `too_low` | ≤300 | 300 시작선 미확보 |
| `excluded_over_experiment_limit` / `excluded_suspected_saturation` | >500 / 포화 의심 | 본 비교 제외, 더 낮은 투입량으로 재측정 |
| `no_samples` | 측정 시작 전 | 피크 판정 불가 |

회복 시간은 `analyze_smoke_recovery.py [측정 폴더]`로 별도 계산한다(포화 판정 포함, 결과 `recovery.csv`).
주 후보 지표는 **PM2.5 300→150의 겉보기 감쇠 시상수**(`tau_300_150_sec`), 보조 후보는 300→100이다.
이 값은 `ln(C)` 대 시간의 선형 회귀에서 구한다. 높은 R²는 그 구간의 직선 적합도를 뜻하며 물리적 타당성의 증명은 아니다.

배경/유입이 일정하고 충분히 혼합된 단일 공간 모델은 `C(t)=C∞+(C0−C∞)exp(−t/τ)`다.
`ln(C−C∞)`를 써야 해당 모델의 τ를 구할 수 있다. 예를 들어 실제 τ=35초, C∞=20인
모의 데이터도 300→150에서 `ln(C)`로 적합하면 τ가 약 39초로 길어지면서 R²는 0.998을 넘는다.
독립적으로 근거가 있는 일정한 C∞를 확보했다면 `--background-pm25 20` 같은 인수로
보정 결과(`*_bg_corrected`)를 추가할 수 있다. 이는 민감도 분석용이며 입력한 값을 자동으로 검증하거나
`metric_ok`의 제외 판정을 해제하지 않는다. 측정 끝 3개 값만으로 배경을 추정하지 않는다.

환기만 있고 다른 입자 손실이 없다면 평형값은 유입 공기 농도다. 하지만 벽면 침착·침강·필터 등의
손실이 있으면 공기청정기가 없어도 그보다 낮아질 수 있다. 단순 모델에서 유입 침투율 P, 환기율 λ,
입자 손실률 k라면 `C∞=PλCroom/(λ+k)`, `τ=1/(λ+k)`다. 따라서 τ를 환기량 자체로 해석하지 않는다.
근거: [NIST 입자 감쇠 연구의 질량수지 모델](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=860910).

- `fit_ok`: 300→150 구간 적합 및 반올림 전 로그 공간 R²≥0.99 여부.
- `metric_ok`: `fit_ok`를 만족하고 회차 완료·환기 시작 기록·표본 카운터 조건을 통과하며,
  고농도 이력이 없는 회차의 **자동 선별 통과**. 정확도·혼합·독립 반복·배경 안정성 검증은 별도다.
  `exclusion_reasons`에 제외 이유를 기록한다. 기존 완료 6회는 모두 >500 이력이 있어 False이며,
  τ와 R²는 탐색을 위해 남긴다. 새 정책으로 제외하는 것이지 기존 후반 데이터가 전부 무의미하다는 뜻은 아니다.
- 최소 10표본·10초, 구간 양끝 근접 관측(시작 ≥270, 끝 ≥135), 구간 내부 6초 초과 공백 없음이 필요하다.
  이는 임시 품질 기준이며 10초만 넘으면 센서 지연 영향이 사라진다는 뜻은 아니다.
  현재 300→150 길이는 21~26초로, 제조사 총 응답시간 ≤10초에 비해 충분히 긴지 예비 실험에서 확인한다.
- 시간 원점은 제거 확인이 아닌 **환기 시작 이벤트**다. 기록된 단조 경과시간(`elapsed_sec`)을 우선하며,
  이전 로그에 그 값이 없으면 PC 수신 시각을 사용한다. 제거 후 OFF 30초인 과거 방식도 구별한다.
- `t_below_*`는 기록 끝까지 다시 초과하지 않은 첫 표본 시각이다. 종료 뒤에도 유지된다는 보장이 없으며,
  3연속 ≤20으로 끝내는 온라인 종료 시각과 다르다. 표본 간 임계 교차를 보간한 시간도 아니다.
- PM2.5 ≤20은 운영상 종료 조건으로 유지한다. 방 공기·침착·노이즈에 민감하므로 주 비교 지표로 쓰지 않는다.
  주변 농도가 높아 달성하지 못하면 최대 시간에서 실패 종료한다. 타임아웃을 회복 완료로 취급하지 않는다.

### 본 실험: 예비 검증 후 9개 조합 × 유효 반복 3회

1. 투입 방식, 확인 지연 허용범위, 분석창, 제외 기준을 먼저 정하고 본 실험 도중 유리한 구간으로 바꾸지 않는다.
2. 9개 조합을 한 번씩 포함한 블록 3개를 만들고, 각 블록 안의 순서를 무작위로 정해 기록한다.
   유효 27회가 목표이며 실패/제외와 재측정도 보존한다. 예비 회차를 사후 선택해 반복 수에 넣지 않는다.
3. 회차별 τ·구간시간·R²·투입 확인 간격·배경·온습도·제외 사유를 같이 본다.
   조합별 유효 n, 평균과 **표본 표준편차(ddof=1)**를 보고한다. 3회는 초기 반복 수이며 근소한 순위 차이의 확정 근거는 아니다.
4. 자연 침착과 환기 효과를 구분하려면 같은 투입·관측 조건의 팬 OFF 대조 회차도 별도로 확보한다.
   300→100의 채택은 독립적인 배경 기록과 반복 결과로 다시 판단한다.

아래 절차는 `--smoke-fans-off`를 사용하지 않는 이전 방식이다.

농도 목표 인수는 사용하지 않는다. 아래 예시는 기본 제거 안내 시간 60초를 쓰는 과거 방식이다.

```powershell
python -X utf8 embedded/new_fan/new_fan_t/measure_smoke_cycle.py --mode experiment --port COM7 --combination 1
```

1. 매 회차 모니터를 연 후 최소 30초 동안 수신한다. 새 PMS 표본 3개 연속 PM2.5 **0~20**이면
   시작 가능하다. 온도는 시작 조건에서 제외하고 기존 칼럼에 계속 기록한다(2026-10-07 사용자 변경).
2. `start` + Enter. 카메라 준비 후 버퍼를 비우고 새 표본으로 조건을 재확인한다.
   60초 내 조건이 맞지 않으면 실패 종료하며 팬을 시작하지 않는다.
3. 해당 조합의 팬을 가동하고 CSV와 사진 저장을 시작한다. **정상 상태 10초**를 기록한다.
   시작 후 이 구간에서 PM2.5가 20을 초과하면 원본을 유지하고 `baseline_pm_above_start_limit` 이벤트를 남긴다.
   시작 조건은 측정 직전에 적용하며, 시작 후 농도 변동만으로 기록을 중단하지 않는다.
4. 10초 종료 알림이 나면 연기를 투입하고 `inserted` + Enter로 실제 투입을 확인한다.
5. `inserted` 확인부터 60초가 되면 제거 안내 및 터미널 벨을 출력한다. 팬 속도는 그대로다.
   발생원을 끄고 제거한 뒤 `removed` + Enter. 알림 시각과 사용자 확인 시각을 분리한다.
   터미널 벨의 실제 소리 여부는 사용 중인 터미널/OS 설정에 따라 다르다.
6. 제거 확인 시 팬 정지를 명령한다. DATA 2개 연속 양쪽 PWM/RPM 0을 확인한 시점부터
   **30초간 OFF**를 유지한다. 이 구간에도 CSV와 사진을 계속 저장하며 조기 완료하지 않는다.
7. OFF 30초가 끝나면 같은 팬 조합을 재가동한다. 이 시점부터 다시 세어서 **새 PM 표본
   3개 연속 PM2.5 ≤20**이면 회복 완료다. 다음 회차 시작 전에도 PM2.5 조건을 다시 확인한다.
8. 사진 저장을 멈추고 팬을 정지한 후 DATA 2개 연속 양쪽 PWM/RPM 0을 확인한다.
   다음 조합은 자동으로 시작하지 않는다. 별도 실행과 사용자 `start`가 필요하다.

실제 연기 제거는 수동이다. `removed` 확인 전에는 수치가 낮아져도 완료하지 않는다.
실제 투입 확인 전에는 60초 타이머를 시작하지 않는다. 확인되지 않은 투입·제거 시각을
임의로 기록하지 않는다. 온도와 습도는 BME가 정상일 때 기존 칼럼에 기록한다.

조합: 1 약/약, 2 약/중, 3 약/강, 4 중/약, 5 중/중, 6 중/강, 7 강/약, 8 강/중, 9 강/강.
약 35%, 중 60%, 강 100%. 카메라는 기본 index 1, 180도 회전하며 전체 정상·투입·제거대기·
OFF 30초·회복 동안 1초 간격으로 저장한다. 사전 모니터 중에는 저장하지 않는다.
`--no-camera`로 생략 가능하고 `--camera-rotation 0`으로 회전을 해제할 수 있다.

## 종료와 오류

`quit`/`stop`, Ctrl+C, 회차 폴더의 STOP 파일은 중단 요청이다. 팬 정지를 시도하고 부분 기록을 보존한다.
새 PMS 미수신 6초, DATA 미수신 5초, 팬 명령 8초 이후 PWM/RPM 이상 또는 카메라 실패도 중단한다.
OFF 30초 중에는 정지 상태가 깨지면 즉시 실패 처리한다.
무한 연기 투입/회복 대기를 막기 위해 전체 실행은 기본 1800초에서 **실패** 종료한다.
`--max-run-sec`으로 변경할 수 있다. 300초 고정 종료나 시간 초과를 정상 회복으로 보고하지 않는다.
중단/실패 시에는 사람이 연기 발생원을 꺼서 제거하고 장비 상태를 확인한다.

## 저장

`data/clean_air_fan_matrix/smoke_cycle/<새 타임스탬프>/<번호_조합>/`

- `sensors.csv`: 기존 `Time,Temp,Humidity,Exhaust_PWM,Intake_PWM,Heat_Load,Exhaust_RPM,Intake_RPM,PM2.5`.

  새 표본 기반 분석에는 이 파일을 사용한다. 시작 직전 재확인 표본은 elapsed_sec=null로 구별한다.
- `events.jsonl`: 실제 측정 시작, 투입/제거 지시와 사용자 확인, 회복·종료·오류.
  `ventilation_verified`는 재가동 후 두 DATA에서 팬 동작을 확인한 시각이다. 환기 명령 시각과 구별한다.
- `status.json`: 실제 최고값, 실제 생성시간(투입 확인~제거 확인), OFF 시간,
  환기 시작부터 회복까지 시간, 제거 확인부터 회복까지 시간, 총 측정시간, 팬 정지 확인, 결과.
- `images/`: 실험 중 JPG 및 촬영 시각 로그. 실패/재측정도 새 폴더를 사용한다.

PMS 표시는 대기환경용 출력이며 절대 질량농도 정확도를 보장하는 보정값이 아니다.
재료를 교체해도 1,000µg/m³ 이상 정확도가 보장되는 것은 아니다.
