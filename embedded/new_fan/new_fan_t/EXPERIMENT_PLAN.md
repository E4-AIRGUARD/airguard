# 흡기·배기 제어 실험 설계 (PM 센서 중심)

2026-09-28 기준. 문(door) 개방 실험은 제외한다 — 카메라에 연기가 보이지 않는 현재 조건에서는
PM 센서 중심의 자동제어를 우선 목표로 잡는다. 지금부터 측정·학습해야 할 질문은 하나다:

> **입자 농도가 올라갔을 때, 흡기·배기를 어떻게 조절해야 빠르게 회복되는가?**

## 0. 선행 확인 — 팬이 실제로 공기를 바꾸는 구조인가

RPM이 올라가는 것과 실제 환기량이 늘어나는 것은 다르다. 기존 구멍 크기·필터·기류 막힘에 따라
결과가 달라지므로, 팬이 돌았다는 기록과 PM이 줄었다는 기록을 항상 함께 확인해야 한다.

| 현재 구조 | 가능한 접근 |
|---|---|
| 외부와 연결된 흡기구·배기구가 있음 | 문을 닫은 상태 그대로 환기 제어 실험 |
| 내부 공기가 필터를 통과해 순환함 | 팬 세기에 따른 입자 제거 성능 측정 |
| 외부 공기 교환도 필터도 없음 | 우선 제거 경로 확보가 필요 — 지금은 혼합·침강 현상만 관측 가능 |

## 1. 카메라 처리 방침

- 현재 설치 상태에서 조명 방향·배경·노출을 고정하고, 연기 발생 전후 원본 영상에 반복 가능한
  차이가 있는지만 짧게 확인한다.
- 차이가 확인되지 않으면 **영상 모델 학습은 보류**한다 — 배경·조명 차이를 "연기 있음" 라벨로
  잘못 학습할 위험이 있다.
- 카메라는 실험 상황 기록용으로만 남기고, 제어 입력은 PM·온습도·팬 상태로 구성한다.
- 센서 시계열 모델을 Jetson에서 실행하면 카메라 없이도 엣지 AI다. 다만 PM 센서는 입자를
  측정하므로 그 값만으로 연기·먼지·물방울을 확정 구분할 수는 없다 (광학식 PM 측정은 입자
  성질에도 영향을 받음 — [Sensirion 백서](https://sensirion.com/media/documents/3D86CBBF/697715E2/Whitepaper_Optical_PM_Sensing__Limits_of_Optical_Sensors.pdf)).

## 2. 실험 1회 = 준비부터 회복까지 끊지 않고 기록

기존 흡·배기구가 있고 기존 시험용 입자 공급을 시작·중단할 수 있다는 전제. 문 개방은 필요 없다.

| 단계 | 수행 방법 | 꼭 남길 기록 |
|---|---|---|
| ① 기준 상태 | 센서 안정화 후 평상시 상태 기록 | 초기 PM·온습도, 팬 상태 |
| ② 입자 공급 | 기존 시험 방식·유입 위치를 일정하게 유지 | 공급 시작·종료 시각, 공급 조건 |
| ③ 제어 시작 | 공급 중단 후 정해진 팬 조합 적용 | 팬 명령 시각, 실제 PWM·RPM |
| ④ 회복 관측 | PM이 기준에 가까워지거나 제한시간까지 계속 측정 | PM 감소 과정, 온습도 변화 |
| ⑤ 다음 실험 준비 | 기존 환기 경로로 초기 상태 복구 | 복구 과정 전체, 다음 실험 시작값 |

- 공급 장치·호스가 통로를 가리는 정도는 회차마다 동일하게 유지한다.
- **발생원을 상자 안에 계속 남겨둔 경우 "공급 종료"로 기록하면 안 된다.** 공급을 중단할 수
  없으면 그 실험은 "지속 유입 중 제어"로 따로 분류한다.

### 시작안 (첫 측정)

- 기준 상태: 약 2분
- 팬 적용 후 관측: 우선 5~10분 — 회복이 안 되면 "미회복"으로 기록하고 이후 실험 시간 조정
- 저장: 1초 간격 센서·팬 통합 로그 (`measure_fan_sensors.py` 형식 유지)
- 팬 변경·환기·회복 구간도 전부 저장 (측정 도중 끊지 않음)

**PMS5003 타이밍 주의:** 1초마다 저장해도 PM 값이 매초 갱신되는 건 아니다 — 안정 상태에서
출력 간격이 약 2.3초일 수 있다. `pms_stale` 플래그와 함께 **마지막 정상 수신 이후 경과시간**을
기록해야 한다. 센서를 슬립에서 깨운 경우 제조사는 안정 데이터까지 최소 30초를 안내한다
([PMS5003 매뉴얼](https://cdn-shop.adafruit.com/product-files/3686/plantower-pms5003-manual_v2-3.pdf)).

## 3. 실험 순서 — 효과 확인 → 세기 비교 → 전환 반응

현재 코드의 약·중·강(35·60·100%)이 실제 장치에서도 유효하다는 전제.

| 순서 | 실험 조건 | 목적 |
|---|---|---|
| 1차 | 무팬 / 흡기 강 / 배기 강 / 흡기·배기 모두 강 | 팬 동작에 따라 회복 차이가 생기는지 확인 |
| 2차 | 효과가 확인된 방식에서 약·중·강 비교 | 필요한 팬 세기 확인 |
| 3차 | 약→중, 중→강, 강→약 전환 | 명령 변경 후 반응 지연과 잔류 효과 확인 |

- **1차는 4조건 × 3회 = 12회**를 초기 탐색으로 진행한다. 3회는 충분한 학습량이 아니라
  반복성을 확인하는 출발점이다.
- 각 회차는 비슷한 초기 PM·온습도에서 시작하고, 조건 순서를 바꿔가며 측정한다 — 초기 농도가
  다르면 종료 농도만으로 "강풍이 더 좋다"고 비교할 수 없다.
- 무팬 조건은 자연 침강·누설만으로 감소하는 양을 구분하기 위한 기준선이다.

## 4. 필요한 데이터 항목

사진 수보다 이 기록의 완전성이 중요하다.

| 중요도 | 데이터 | 필요한 이유 |
|---|---|---|
| 필수 | `run_id`, 시각, 장치 경과시간(`elapsed_ms`) | 실험 구분과 시간 정렬 |
| 필수 | 내부 PM2.5, 가능하면 PM1.0·PM10 | 제어 대상과 변화 추세 |
| 필수 | 내부 온도·상대습도 | 실험 조건 및 센서값 해석 |
| 필수 | 흡기·배기 명령 PWM, 실제 RPM | 지시한 동작과 실제 동작 구분 |
| 필수 | 팬 명령 변경 시각 | 제어 반응 지연 계산 |
| 필수 | 센서 오류(`bme_err`), 마지막 정상 수신 시각(`pms_stale`) | 무응답·반복값을 정상 측정과 구분 |
| 필수 | 입자 공급 시작·종료, 실험 단계 | 공급 변화와 팬 효과 구분 |
| 회차별 필수 | 팬·배선·펌웨어 버전, 센서 위치, 필터·통로 상태 | 서로 다른 장치 조건이 섞이는 것 방지 |
| 권장 | 외부 PM2.5 | 흡입 공기가 내부보다 깨끗한지 판단 |
| 목적별 추가 | 실제 전력, 풍량, 소음 | 절전·환기량·저소음 성능을 주장하려면 필요 |

`measure_fan_sensors.py`의 현재 CSV 컬럼(`pc_timestamp, elapsed_ms, duty_in_pct, rpm_in,
duty_out_pct, rpm_out, temp_c, rh_pct, pressure_hpa, pm1_0, pm2_5, pm10, bme_err, pms_stale`)은
위 필수 항목 대부분을 이미 포함한다. 빠진 것: `run_id`(파일명/폴더명으로 대체 중), 입자 공급
시작·종료 마커, 팬·배선·펌웨어 버전 태그, 외부 PM.

### 외부 PM 센서

센서 하나를 추가할 여유가 있다면 환기 제어에서는 **외부 PM 센서를 우선 검토**한다. 내부 PM만
으로는 팬을 켠 뒤 농도가 오른 이유가 외부 유입인지 내부 발생인지 구분하기 어렵다. 두 센서를
쓰면 설치 전 같은 장소에서 함께 측정해 서로의 차이도 확인해야 한다.

추가 센서가 없다면 초기 실험 범위를 **외부 조건이 비교적 일정한 상황의 내부 농도 회복**으로
제한한다. 측정하지 않은 외부 PM을 0으로 채워 넣지 않는다.

### PMS5003 설치 위치

팬 바람이 직접 때리는 곳에 놓으면 설치 영향이 생길 수 있다. 제조사도 기류 경로의 직접 설치를
피하거나 차폐 구조를 두도록 안내한다. 위치를 고정하고, 입자는 통하되 직접 바람의 영향은
줄이는 배치를 사용한다 ([설치 지침](https://cdn-shop.adafruit.com/product-files/3686/plantower-pms5003-manual_v2-3.pdf)).

## 5. 기존 데이터 활용 범위

`data/{no_smoke,smoke_inside,smoke_outside,heat_5s}/{low,medium,strong}/` 아래 기존 측정을
다음처럼 구분해서 쓴다 — 버리지 않는다.

- **PWM·RPM 데이터:** 현재 하드웨어(Tach GPIO5 이동 이후)와 일치하는 회차만 팬 반응 분석에
  사용. 그 이전 회차는 배선이 달랐으므로 rpm 절대값을 섞어 비교하지 않는다.
- **PM 정상 수신 구간(`pms_stale=0`):** 초기 환경 변화 모델의 후보 데이터로 활용.
- **`pms_stale=1`인 PM=0 구간:** PM은 결측 처리. 온도·RPM 등 나머지 컬럼까지 버릴 필요는 없다.
- **이전 배기 PWM이 수동 연결 라벨이었던 데이터:** 현재 연속 속도 제어 데이터와 분리해서 관리.
- **팬 전환 구간이 빠진 데이터(예: 지금까지의 `intake_weak`/`intake_medium`/`intake_strong`처럼
  단계별로 파일이 나뉜 회차):** 일정 팬 상태 분석에는 쓰되, 전환 반응 학습에는 한계가 있음 —
  §2 방식(전 구간 연속 로깅)으로 다시 모아야 전환 반응을 학습할 수 있다.
- **연기가 보이지 않는 영상:** 실험 기록으로 보존하고, 연기 인식 성능을 입증하는 자료로는
  사용하지 않는다.

## 6. AI 모델링 목표

첫 목표는 "최적 팬 정답 맞히기"가 아니라 **"팬 동작 후 변화 예측"**이다.

> 최근 PM·온습도·RPM 추세 + 적용할 흡기·배기 세기 → 앞으로 10~30초 뒤의 PM 변화

예측 시간은 초기 실험에서 확인한 실제 반응 속도에 맞춰 조정한다. Jetson은 검증된 후보 동작의
예측 결과를 비교하고, ESP32는 팬 구동과 센서·통신 오류 처리를 담당한다.

## 7. 평가 지표

모델 정확도 외에 다음을 함께 본다.

- 목표 농도 도달 시간
- 목표 초과 농도의 시간 누적값
- 팬 전환 횟수
- 실패·미회복 횟수

전력을 측정하지 않았다면 "PWM 사용량을 줄였다"는 결과와 "실제 절전 효과"는 구분해서 기술한다.

## 8. 지금 가장 먼저 할 일

문과 카메라를 제외한 상태에서 **무팬·흡기·배기·동시 구동의 회복 곡선을 비교하는 12회 초기
실험** (§3의 1차)을 진행한다. 여기서 팬에 따른 차이가 반복해서 확인되면, 그때 약·중·강
데이터를 확장하고 예측 모델을 붙이는 순서로 넘어간다.
