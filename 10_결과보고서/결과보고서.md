## 1. 문제정의

### 1-1. 문제와 목표

같은 팬 출력으로 운전해도 초기 온도, 입자 농도, 열 부하에 따라 회복 시간이 달라집니다. 팬을 켰다는 사실만으로는 목표 상태에 도달했는지, 팬을 필요 이상으로 돌렸는지 알 수 없습니다. 이 프로젝트는 다음 질문에 답하는 것을 목표로 했습니다.

> 현재 환경에서 어떤 흡기·배기 팬 조건으로 얼마나 가동해야 목표 상태에 도달하는가?

검증 대상은 실제 배터리 시설이 아니라 센서, 카메라, 흡기·배기 팬을 갖춘 실험용 챔버입니다. 배터리 열폭주 방지, 소화, 유해가스 감지, 제습 성능은 검증 범위에 포함하지 않았습니다.

### 1-2. 판단 기준

| 항목       | 기준                                              |
| ---------- | ------------------------------------------------- |
| 온도 회복  | T < 26°C (26.0°C는 미충족)                        |
| PM2.5 회복 | PM2.5 ≤ 50 µg/m³                                  |
| 회복 확정  | 위 조건을 유효한 센서값으로 정해진 시간 동안 유지 |
| 팬 조건    | 흡기·배기 각각 PWM 35 / 60 / 100, 총 9개 조합     |

이 값은 실험용 기준이며 배터리 보관 안전기준이나 법정 기준이 아닙니다.

### 1-3. 시스템 구성

| 구분 | 구성                                                                 |
| ---- | -------------------------------------------------------------------- |
| 입력 | PMS5003(PM2.5), BME280(온도·습도), USB 웹캠(U20CAM-720P), 팬 PWM·RPM |
| 수집 | ESP32 WROOM-32                                                       |
| 처리 | NVIDIA Jetson Orin Nano                                              |
| 출력 | 흡기·배기 팬, 웹 대시보드                                            |
| 기록 | Aiven MySQL, Jetson 로컬 저장소                                      |

## 2. 데이터

### 2-1. 센서 데이터

흡기·배기 PWM 35 / 60 / 100을 조합한 9개 조건에서 BASE(기준), HEAT(가열·냉각), SMOKE(연기 회복) 실험을 했습니다.

| 유형  | 규모                                    | 용도                       |
| ----- | --------------------------------------- | -------------------------- |
| BASE  | 3,000행 (팬 정지 300행 + 9조합 2,700행) | 기준 상태와 팬 작동 특성   |
| HEAT  | 26회, 3,402행                           | 온도 하강 추세와 회복 속도 |
| SMOKE | 27회, PM 관측 5,124개                   | 농도 감소 추세와 회복 속도 |

팬 제어 모델은 PM500에서 PM50까지의 도달 시간 측정 79회(가중치 반영 161행)로 학습했습니다. 온도 LSTM은 가열 27 run과 무가열 정상 팬 운전 9 run, 총 36 run·6,218행을 사용했고 실험 단위로 train/validation/test를 나눴습니다.

### 2-2. 이미지 데이터

| 구분   | 내용                                                                   |
| ------ | ---------------------------------------------------------------------- |
| 과제   | 연기 있음(smoke) / 없음(no_smoke) 이진 분류                            |
| 라벨링 | 사람이 영상의 시간 구간을 지정하고 구간 안 프레임에 같은 라벨을 적용   |
| 분할   | 학습 2,590장 / 검증 894장 / 시험 311장 (시험: 연기 123, 연기 없음 188) |
| 전처리 | 640×360 크기 조정 → 흑백 → CLAHE → INFERNO 색상표                      |
| 합성   | 모기향 붙이기·지우기·옮기기, 지운 흔적 대조군                          |

INFERNO는 의사색상이며 온도 측정값이 아닙니다. 연기 발생원은 모기향과 드라이아이스입니다. 연기 라벨은 눈에 보이는 연기 기준이며 센서 기준 초과와 같은 뜻이 아닙니다.

학습 이미지에는 연기와 함께 찍힌 모기향이 많아서, 모델이 모기향 모양을 연기 신호로 학습하는 문제가 있었습니다. 이를 줄이려고 불을 붙이지 않은 모기향 장면과 모기향 합성 이미지를 추가했습니다.

## 3. 모델

| 구분 | 모델                                                              | 입력 → 출력                                        | 핵심 결과                                                                              |
| ---- | ----------------------------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Ⅰ    | 이미지(웹캠) 기반 연기 판별 모델 (`smoke_cls_v4.pt`, YOLO11n-cls) | 웹캠 프레임 → smoke / no_smoke                     | test 311장, 기준 0.40: 정확도 92.0%, 재현율 92.7%, 정밀도 87.7%, F1 0.901, AUROC 0.977 |
| Ⅱ    | 센서(PMS) 기반 팬 자동제어 모델 (`models/model.json`)             | PM, 흡기·배기 PWM → PM500에서 PM50까지의 도달 시간 | 독립 평가 평균 오차 4.8초(10/18), 13.2초(Jetson), 조합 하나 제외 예측 5.8초            |
| Ⅲ    | 온도 예측·팬 제어 모델 (`lstm_temperature_trajectory_v6.pt`)      | 최근 8표본 → 1·3·5초 뒤 온도, 26°C 위험 점수       | 5초 예측 MAE 0.1758°C, 상한 판정 정확도 98.50%, FP 6 / FN 17 (개발 test 1,532시점)     |

### 3-1. 이미지 모델

- 켜기 기준은 검증 세트에서 F1이 가장 높은 0.40입니다. 기준을 0.30으로 낮추면 재현율 96.7%, 오탐률 11.7%이고, 0.50으로 올리면 재현율 87.8%, 오탐률 6.4%입니다.
- 오탐 16장은 모두 연기가 없고 모기향과 받침이 보이는 장면이었습니다. 미탐 9장은 가는 연기 줄기였습니다.
- 목표로 둔 재현율 95% 이상, 오탐률 1% 이하는 달성하지 못했습니다(실험실 test 기준 재현율 92.7%, 오탐률 8.5%).

### 3-2. 팬 제어 모델

- 시간 예측: 1/T = k0 + k1·s(흡기) + k2·s(배기) + k3·s(흡기)·s(배기). 계수 5개의 회귀식이며 신경망이 아닙니다.
- 제어기: 마감(70초) 안에 PM50에 도달하는 조합 중 추정 에너지가 가장 적은 것을 동적계획법으로 고릅니다. 급상승 시 최고속, 실시간 속도 보정, 정체 감지, 최소 유지 25초를 적용했습니다.
- 에너지는 RPM 기반 추정값이며 전력계로 측정한 값이 아닙니다.

### 3-3. 온도 모델

- 1-layer LSTM(hidden 32, 파라미터 5,764개)이 1·3·5초 뒤 온도를 예측하고, 별도 제어기가 9개 팬 조합 중 하나를 고릅니다. 모델이 직접 PWM을 출력하지 않습니다.
- 같은 분할의 회귀 baseline과 비교하면 FP는 10→6, FN은 22→17로 줄었지만 전체 MAE는 회귀(0.1535°C)가 v6(0.1758°C)보다 낮았습니다. 가열 run의 MAE는 v6가 0.1020°C로 회귀(0.1756°C)보다 낮고, 무가열 run에서는 반대입니다.
- 9 run 쌍체 bootstrap의 MAE 차이 구간이 0을 포함해서 v6의 전체 우위를 통계적으로 확정하지 않았습니다.

## 4. Jetson 통합

Jetson에서는 두 프로세스가 돌아가며 HTTP로만 연결됩니다.

| 프로세스         | 역할                                                        | 포트 |
| ---------------- | ----------------------------------------------------------- | ---- |
| 통합 제어기      | ESP32 센서 수신 → 온도/PM 판정 → 팬 PWM 전송 → 사건·DB 저장 | 8095 |
| 카메라 연기 서버 | 카메라 → 전처리 → YOLO11n-cls 추론 → 연기 알림 판정         | 8092 |

- 팬은 PMS5003 PM2.5와 BME280 온도로만 움직입니다. 카메라 연기 확률은 팬 제어 입력이 아니라 사건 사진과 알림에 쓰입니다.
- 온도 요구와 PM 요구는 흡기·배기별로 큰 값을 골라 합칩니다.
- 센서 수신부터 팬 전송까지 1초마다 한 번 판단합니다.
- 대시보드 연결이 끊기면 팬 명령을 0/0으로 둡니다.

| 환경           | 값                                                |
| -------------- | ------------------------------------------------- |
| 보드           | Jetson Orin Nano 7.6GB                            |
| 라이브러리     | TensorRT 10.3.0, torch 2.8.0, Ultralytics 8.4.118 |
| 연기 모델 실행 | `.pt`를 TensorRT FP16 `.engine`으로 변환해 사용   |
| 온도 모델 실행 | PyTorch CPU 원본                                  |

상세는 [Jetson 실행 코드](../04_Jetson_실행코드/Jetson_실행코드.md)를 참조합니다.

## 5. Benchmark

### 5-1. 연기 모델 TensorRT FP16 (Jetson Orin Nano, 입력 640, 600프레임, 2회 측정)

| 항목            | `.pt`           | TensorRT FP16        | 변화                 |
| --------------- | --------------- | -------------------- | -------------------- |
| 추론 시간 평균  | 36.14 / 35.14ms | 28.36 / 27.33ms      | -21.5% / -22.2%      |
| 초당 프레임     | 25.2 / 25.9     | 31.4 / 32.5          | +24.6% / +25.4%      |
| GPU 메모리      | 62.7MB          | 9.4MB                | -85%                 |
| 전력 평균       | 6.49W           | 5.66W                | -12.8%               |
| 프레임당 에너지 | 약 251mJ        | 약 174mJ             | -30%                 |
| 정확도          | 기준            | 점수 차이 최대 0.003 | 판정 바뀐 프레임 0개 |

속도는 약 20~22% 단축됐고 판정은 바뀌지 않았습니다. 데모는 3프레임마다 한 번 판정하고 카메라가 약 10fps라서 `.pt`로도 속도는 충분했습니다. 변환은 손해 없는 개선이지만 필수는 아니었습니다. `.engine`은 기기와 TensorRT 버전에 묶여 있어서 기기마다 다시 변환해야 합니다.

### 5-2. 팬 자동제어 개선 전후

| 항목                                     | 전         | 후        |
| ---------------------------------------- | ---------- | --------- |
| PM50까지 평균 시간                       | 168초      | 90초      |
| 평균 추정 에너지                         | 206 J      | 103 J     |
| 불가능 판정으로 최고속 강제한 횟수(최대) | 197회      | 27회      |
| PM50까지 남은 시간 오차                  | 8.4~10.2초 | 6.4~7.9초 |

전은 유효 2회, 후는 3회뿐이고 연기 양도 달라서 엄밀한 비교는 아닙니다. 팬 제어 모델은 계수 5개의 회귀식이라 TensorRT 최적화 대상이 아닙니다.

### 5-3. 최종 측정 (자동제어, 고정 100/100, 고정 35/35 각 3회)

| 방식         | PM50까지 평균 | 추정 에너지 평균 | 마감 70초 달성 |
| ------------ | ------------- | ---------------- | -------------- |
| 자동제어     | 90초          | 103 J            | 2/3            |
| 고정 100/100 | 58초          | 188 J            | 2/3            |
| 고정 35/35   | 87초          | 23 J             | 0/3            |

정상 동작한 2회는 100/100과 비슷한 속도로 끝났고 에너지는 55~60% 적었습니다. 에너지가 가장 적은 것은 35/35입니다.

### 5-4. 온도 모델 처리 시간 (Jetson, PyTorch CPU, 1,612 윈도우)

| 구간          | 온도 단독 평균 | 연기 추론 동시 실행 평균 |
| ------------- | -------------- | ------------------------ |
| 단일 예측     | 1.38 ms        | 1.36 ms                  |
| 9개 후보 평가 | 12.94 ms       | 12.69 ms                 |

1초 판단 주기를 넘은 경우는 두 조건 모두 0/1,612회였습니다. 온도 모델에는 추가 변환을 적용하지 않았습니다. 센서 수신, 팬 통신, DB 저장은 측정에서 제외했고 조건당 1회 측정입니다.

## 6. DB와 장치

### 6-1. 기록 방식

이상이 시작되면 이벤트를 만들고, 회복이 확정될 때까지의 센서값·팬 상태·사진을 `event_id`로 연결합니다.

| 테이블                | 내용                                                                        |
| --------------------- | --------------------------------------------------------------------------- |
| `e4_recovery_events`  | 이벤트 요약(시작·최초 도달·회복·종료 시각, 상태, 회복 시간, 시작 시점 설정) |
| `e4_recovery_samples` | 이벤트 내 센서·팬 시계열(온도, 습도, PM2.5, PWM, RPM, 유효성 플래그)        |
| `e4_recovery_photos`  | 사진 메타데이터(시각, 단계, 상대 경로). 사진 원본은 Jetson에 저장           |

- 기록 구간은 이상 발생 순간부터 회복 확정 시점까지입니다(`pre_seconds=0`, `post_seconds=0`).
- 정상 상태의 대시보드 실시간 값은 로컬 SQLite에 두고, Aiven에는 이벤트 기록만 전송합니다.
- 전송은 로컬 대기열에서 트랜잭션 단위로 하며, 성공한 뒤에만 대기 기록을 지웁니다. 같은 UUID에 UPSERT를 써서 재전송해도 행이 중복되지 않습니다.
- 프로세스가 갑자기 종료되면 다음 시작 때 진행 중이던 이벤트를 `interrupted`로 처리하고 정상 회복 통계에서 제외합니다.

### 6-2. 조회

대시보드는 Jetson 서버의 읽기 전용 API(`/api/live`, `/api/history`, `/api/events`, `/api/events/{event_id}` 등)로 조회합니다. 날짜별 이벤트 목록, 이벤트별 센서 시계열·사진, CSV 내보내기를 지원합니다. DB 시각은 UTC이고 API는 한국 날짜 기준으로 조회합니다. 상세는 [DB 구조·조회 방식](../07_DB구조_조회방식/DB구조_조회방식.md)을 참조합니다.

## 7. 통합 테스트와 현장변수 대응

이 장은 별도 산출물이 없는 내용을 다룹니다. 요구된 조명, 거리, 각도 조건별 시험은 수행하지 않았고, 아래 표에는 기록으로 확인되는 것만 적었습니다.

### 7-1. 조건별 테스트 결과표

| 조건           | 시험 여부 | 결과                                                                                                                                              |
| -------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 조명           | 미측정    | 조도를 바꿔 반복한 시험 기록 없음. 장면 구성 단계에서 낮은 구도 햇빛, 그림자, 반사 장면을 학습 데이터에 포함했을 뿐 조도별 성능은 측정하지 않았음 |
| 거리           | 미측정    | 카메라와 연기 발생원의 거리를 바꾼 시험 기록 없음. 카메라는 고정 위치에서 사용                                                                    |
| 각도           | 미측정    | 카메라 각도를 바꾼 시험 기록 없음. 학습 때 회전 15°, 이동, 확대·축소 증강을 적용했으나 각도별 성능은 측정하지 않았음                              |

| 대상                                       | 변경                      | 전                              | 후                              |

| 온도 제어 PWM 변경 횟수 (실장비 시험)      | v4 → v5 → v6              | 20회                            | 8회 → 6회                       |
| 온도 제어 26°C 이상 시간 (실장비 시험)     | 위와 같음                 | v4 81초                         | v5 86초, v6 73초                |

해석에 주의할 점이 있습니다.

- v3에서 v4로 오탐은 크게 줄었지만 연기를 켜는 비율은 낮아졌습니다. 같은 기준 0.40에서의 교환 관계입니다. 기준을 0.30으로 낮추면 반응은 v3 수준으로 돌아오고 오탐은 2.1초가 남습니다.
- 팬 제어의 전은 유효 2회뿐이고 연기 양이 달라서 엄밀한 비교가 아닙니다.
- 온도 제어의 v4/v5/v6 시험은 초기 온도·가열 시간·실행 길이가 달라 동일 조건의 반복 시험이 아닙니다. PWM 변경 횟수가 적다는 것만으로 제어가 더 좋다고 판단하지 않았습니다. 세 구성 모두 26°C 초과를 막지 못했습니다.
- 온도 제어 시험은 과거 6후보 정책의 결과이고, 현재 9후보 정책을 실장비에서 검증한 것이 아닙니다.

## 9. 결론

- 챔버 실측 데이터로 연기 판별(이미지), 팬 자동제어(PM), 온도 예측(LSTM)의 세 모델을 만들고, Jetson Orin Nano에서 센서 수집·판단·팬 제어·이벤트 기록·사진 저장을 한 흐름으로 연결했습니다.
- 연기 판별 모델은 test 311장에서 재현율 92.7%, 오탐률 8.5%였고, TensorRT FP16 변환으로 추론 시간을 약 20% 줄이면서 판정은 바뀌지 않았습니다. 목표로 둔 재현율 95% 이상, 오탐률 1% 이하에는 미치지 못했습니다.
- 팬 자동제어는 정상 동작한 회차에서 고정 100/100과 비슷한 속도로 에너지를 55~60% 적게 썼습니다. 다만 조건당 3회라 자동제어가 더 낫다고 단정할 수 없습니다.
- 모기향 오탐, 가는 연기 미탐, PM50 근처 정체, 온도 급상승 미탐이 확인된 실패 사례입니다. 조명·거리·각도·장시간 시험은 하지 못했고, 다음 단계의 우선 과제로 남겼습니다.
