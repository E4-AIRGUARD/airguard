# 1. 문제정의서

## 프로젝트 개요

**E4 AIRGUARD는 챔버 실측 데이터를 활용해 환경 이상을 감지하고, 회복 시간과 팬 운전 조건을 평가하는 Jetson 기반 Edge AI 환기 제어 프로토타입이다.**

핵심 질문은 **“현재 환경에서 어떤 흡기·배기 팬 조건으로 얼마나 가동해야 목표 상태에 도달하는가?”**이다. 팬 가동 여부와 함께 기준 도달, 유지 여부, 실제 운전 결과를 기록해 다음 운전 판단의 근거로 활용한다.

## 1. 현장 문제와 적용 배경

환경 관리에서는 같은 팬 출력으로 운전하더라도 초기 온도, 입자 농도, 열 부하와 공기 흐름에 따라 회복 시간이 달라질 수 있다. 일정한 출력이나 시간만으로 운전하면 목표 도달 여부와 과도한 가동 여부를 구분하기 어렵다. 따라서 환경 변화, 적용한 팬 조건, 회복 결과를 하나의 기록으로 연결할 필요가 있다.

본 프로젝트는 배터리 이송·보관 환경을 적용 배경으로 삼는다. 온도와 수분 등 보관 환경의 변화에 주목하되, 검증 대상은 실제 배터리 시설이 아닌 센서·카메라·흡배기 팬을 갖춘 실험용 챔버이다. 컨테이너형 ESS의 운전 중 열 관리와 배터리 이송·보관은 서로 다른 운용 조건이므로 동일한 기준을 적용한다고 가정하지 않는다.

| 해결하려는 문제 | 프로젝트의 접근 |
| --- | --- |
| 환경 상태에 따라 필요한 운전 시간이 달라짐 | 실측 시계열을 수집하고 회복 시간을 비교 |
| 팬 가동만으로 목표 회복 여부를 알기 어려움 | 기준 도달과 일정 시간 유지 여부를 구분 |
| 센서값·팬 상태·현장 이미지가 분리됨 | 이상 발생부터 회복까지 `event_id`로 연결 |
| 팬 조건을 선택할 근거가 부족함 | 조건별 실험 결과와 AI 예측을 비교·검증 |

기존 스마트 컨테이너나 자동 공조 시스템 전체가 수동 운전만 한다는 주장은 하지 않는다. AIRGUARD의 의의는 소형 실험 장치에서 **측정 → 판단 → 팬 운전 → 회복 확인 → 이력 조회**를 연결하고, 조건별 회복을 비교할 수 있는 검증 기반을 만드는 데 있다.

## 2. 사용자와 사용 시나리오

| 사용자 | 필요한 정보와 기능 |
| --- | --- |
| 챔버 운전자 | 현재 온습도·PM2.5, 팬 PWM·RPM, 카메라 화면, 이상·회복 상태 |
| 실험·모델 개발 담당자 | 초기 조건과 팬 조합별 센서 추이, 회복 시간, 이미지, 예측 오차 |
| 시스템 관리 담당자 | 센서 수신 지연, DB 전송 상태, 중단 이벤트와 누락 기록 |

1. 정상 상태에서는 센서·카메라와 팬 상태를 로컬 대시보드로 확인한다.
2. 설정 기준 초과가 감지되면 이벤트를 생성하고 센서값과 현장 이미지를 기록한다.
3. 제어 모듈이 적용한 팬 조건과 환경 변화를 함께 확인한다.
4. 판정 대상 센서가 모두 기준 범위에 들어와 지정 시간 동안 유지되면 회복으로 판정한다.
5. 이벤트별 센서 추이·사진·회복 시간을 조회해 운전 조건을 비교한다.

## 3. 시스템 입력과 출력

| 구분 | 구성 | 역할 |
| --- | --- | --- |
| 입력 | PMS5003 | PM2.5 측정 |
| 입력 | BME280 | 온도·상대습도 측정 |
| 입력 | USB U20CAM-720P | 챔버 이미지 수집, 연기 징후 판단용 입력 |
| 입력 | 팬 적용 PWM·RPM | 실제 운전 조건과 회전 상태 확인 |
| 수집 | ESP32 WROOM-32 | 센서·팬 상태 전달, 팬 구동 인터페이스 |
| 처리 | NVIDIA Jetson Orin Nano | 데이터 수신·유효성 확인 및 AI·제어 통합 대상 |
| 출력 | 흡기·배기 팬 | 팬 운전 조건 적용 |
| 출력 | 웹 대시보드 | 현재 상태, 센서 추이, 이벤트 이력, CFD 영상 |
| 기록 | Aiven MySQL + Jetson 로컬 저장소 | 이벤트 센서 기록·사진 메타데이터 및 사진 원본 보관 |

PPT의 수집 계획은 1초 주기이다. 실제 유효 수신 주기와 누락률은 실장비 로그로 확인한다. 프로젝트의 회복 판정 대상은 온도와 PM2.5이며 습도는 감시 항목이다. 실제 DB 패키지의 설정 반영 상태는 5절에서 별도로 구분한다.

## 4. AI와 Edge 처리를 활용하려는 이유

임계값 비교는 이상 발생 여부를 판단하는 기준이 될 수 있다. AI는 여기에 **환경 변화와 팬 조건을 함께 반영한 회복 시간 예측**, **영상 기반 연기 징후 판단**, **팬 조건 선택의 근거 제공**을 더하는 목적으로 검증한다.

| 역할 | 검증할 내용 | 비교 기준 |
| --- | --- | --- |
| 연기 영상 판단 | 연기·비연기 구분 및 방해물에 대한 오탐·미탐 | 비연기 장면, 센서 기반 판정 |
| 회복 시간 예측 | 초기 상태·시계열·팬 조건으로 목표 도달 시간 예측 | 단순 예측 모델 및 실측 회복 시간 |
| 팬 조건 선택 | 회복 성능과 팬 운전량을 고려한 조건 선택 | 고정 PWM·규칙 기반 운전 |

Jetson에서 입력 처리와 추론을 수행하는 구성은 외부 DB 연결과 현장 판단 경로를 분리하기 위한 선택이다. DB 전송이 지연될 때는 로컬 대기열에 기록을 보관한다. 다만 네트워크 단절 중 AI 제어의 연속 동작은 별도 통합 시험으로 입증해야 한다.

AI가 반드시 필요하거나 기존 제어보다 우수하다고 전제하지 않는다. 동일한 실험 조건에서 예측 오차, 회복 성능, 지연 시간과 운전량을 비교해 활용 효과를 판단한다.

## 5. 정상·이상·회복의 판단 기준

### 확정한 회복 기준

| 항목 | 회복 조건 | 경계값 해석 |
| --- | --- | --- |
| 주변 공기 온도 | **`T < 26°C`** | 26°C 미만. **26.0°C는 회복 조건을 만족하지 않음** |
| PM2.5 | **`PM2.5 ≤ 50 µg/m³`** | 50 µg/m³ 이하. 50.0 µg/m³ 포함 |
| 회복 확정 | 판정 대상 센서가 모두 유효하고 위 조건을 `hold_seconds` 동안 유지 | 최초 기준 도달과 회복 확정을 구분 |
| 이벤트 기록 | 이상 발생 순간부터 회복 확정 시점까지 | 시작·확정 측정 포함, `pre_seconds=0`, `post_seconds=0` |

온도가 25.9°C이면 온도 조건을 만족하지만 26.0°C 또는 26.1°C이면 만족하지 않는다. 온도 조건만 만족해도 PM2.5가 기준을 벗어나거나 센서값이 무효이면 회복으로 확정하지 않는다. 위 값은 실험용 회복 기준이며 배터리 보관 안전기준이나 법정 기준이 아니다.

### 프로젝트에서 요구하는 회복·기록 동작

- **이상 시작:** 설정된 이상 발생 조건이 충족되면 이벤트를 생성한다. 이상 시작 임계값과 회복 임계값의 관계는 제어 설정에서 명시한다.
- **회복 후보:** 온도 `< 26°C`와 PM2.5 `≤ 50 µg/m³`를 모두 만족하고 두 센서값이 유효하면 정상 유지 시간을 측정한다.
- **회복 확정:** 회복 후보 상태가 `hold_seconds` 동안 유지되면 회복 시각을 기록한다.
- **재이상·결측·시간 간격 초과:** 정상 유지 시간을 초기화하고 회복 확정 전에는 같은 이벤트의 기록을 계속한다.
- **완료:** 회복 확정 시점의 측정값을 포함해 즉시 기록을 종료한다. 완료 뒤 재이상은 새 이벤트로 기록한다.
- **중단:** 수집 프로세스 종료·재시작으로 끝난 이벤트를 정상 회복과 구분한다.

결측값은 정상값 0으로 치환하지 않는다. 26°C에서 회복하지 않는다는 조건만으로 이상 시작 조건까지 자동으로 결정되는 것은 아니다.

### 실행 코드 반영 상태 — 2026-10-21 확인

프로젝트 기준과 로컬 코드의 현재 설정을 구분한다. 기존 문서의 ‘온도 25.0 / PM2.5 20.0’ 비교표는 이전 사본의 설정이므로 현재 상태 설명에서 제외했다.

- 최근 첨부한 `E4_AIRGUARD_Aiven_DB/config.json`에는 `thresholds={"pm25":25.0}`만 있으며, 온도 판정 항목은 없다. PM2.5도 프로젝트 회복 기준 50과 다르다.
- 기존 `logger.py`는 설정 항목 전체에 상한 이하(`≤`) 비교를 사용한다. 온도값을 26으로 추가하는 것만으로는 `T < 26°C`가 구현되지 않는다. 온도는 `<`, PM2.5는 `≤`로 구분해 적용해야 한다.
- 기존 설정의 정상 유지 시간은 `hold_seconds=10`, 허용 측정 간격은 `max_gap_seconds=2.5`이다. 이를 온도·PM 회복 조건에 함께 적용하는지 실장비에서 확인한다.
- 복구된 Jetson 적용패키지는 설치 시 `pre_seconds=0`, `post_seconds=0`을 적용한다. 기존 DB 폴더의 config.json 자체는 설치 전까지 30/30일 수 있다.
- 온도 비교 연산과 회복 기준값의 실행 코드 반영은 아직 완료되지 않았다. 현재 문서 수정은 구현 완료를 뜻하지 않는다.
- AI 이미지 결과를 이벤트 시작 조건에 직접 연결하는 기능은 확인한 기록 코드에 없다.

적용 후에는 온도 25.9·26.0·26.1°C와 PM2.5 49·50·51 µg/m³, 결측 및 정상 유지 시간 조건을 조합해 경계값 시험을 수행한다.

## 6. 실험 범위

PPT에 제시된 실험은 BASE·HEAT·SMOKE이며 흡기와 배기 각각 PWM 35·60·100의 3단계를 조합한 9개 조건을 비교한다.

OpenFOAM은 사전 계산된 결과 영상을 상황·팬 조합에 맞춰 불러오는 라이브러리이다. 실시간 CFD 계산이나 센서값을 그대로 복원하는 영상으로 설명하지 않는다.

본 프로젝트의 검증 범위는 챔버 내 환경 회복과 시스템 연계이다. 실제 배터리의 열폭주 방지, 소화, 유해가스 감지, 제습 성능은 검증 범위에 포함하지 않는다. 팬 PWM과 운전 시간으로 산출한 운전량은 실제 소비전력과 구분한다.

## 7. 성공 기준과 검증 방법

아래는 평가 계획이며 달성 결과를 의미하지 않는다. 정량 목표치와 반복 횟수는 팀이 시험 전에 확정하고, 결과와 함께 공개한다.

| 평가 대상 | 성공 판단·지표 | 제출할 증거 |
| --- | --- | --- |
| 데이터 수신 | 시각·유효성·PWM·RPM이 일관되게 기록됨 | 연속 수신 로그, 누락률 |
| 이상·회복 판정 | 초과 시 이벤트 생성, 유지 후 회복, 결측을 회복으로 오판하지 않음 | 상태 전이 시험, DB 기록 |
| AI 연기 판단 | 연기와 방해물 구분을 평가함 | Precision·Recall·F1, 오탐·미탐 사례 |
| AI 회복 예측 | 미학습 실험에서 예측값과 실측값을 비교함 | MAE·RMSE, 조건별 오차 |
| 팬 조건 선택 | 같은 초기 조건에서 기준 운전과 비교함 | 회복 시간·목표 도달률·팬 운전량 |
| Edge 통합 | 입력→판단→팬 반응→기록을 실제 장비에서 재현함 | 시연 영상, 지연 시간, 장시간 실행 기록 |
| DB 연계 | 이벤트와 센서·사진이 연결되고 재전송 중복을 방지함 | 이벤트 상세 조회, 네트워크 실패·복구 시험 |

동일 실험에서 연속 촬영한 프레임이나 시계열이 학습·시험에 섞이지 않도록 실험·영상 단위로 분할한다. 임계값과 회복 유지 시간도 시험 전에 고정한다.

## 8. 현재 확인 범위와 남은 작업

PPT는 센서·팬 실험, 전처리, 대시보드 화면을 현재 구현으로 소개하고 Jetson·AI·DB 연결을 통합 검증 대상으로 제시한다. 확인한 로컬 코드에는 이벤트 기록·전송과 대시보드 조회 경로가 있다. 이 문서는 실제 Jetson 배포 완료나 AI 성능 수치를 입증하지 않는다.

남은 작업은 확정된 회복 기준의 코드 반영, AI 결과와 제어·이벤트의 연결 확인, 실제 장비 연속 운전, 운영 DB 스키마 비교이다. 상세 저장·조회 구조는 별도 문서 「7. DB 구조·조회 방식」을 참조한다.
